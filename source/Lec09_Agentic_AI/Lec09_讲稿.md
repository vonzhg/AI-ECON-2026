## 本讲概览

这一讲我们从"会聊天的 AI"跨到"会动手干活的 AI"——也就是**智能体式 AI（agentic AI）**用在研究工作流上。具体的例子是终端里运行的智能体工具，如 Claude Code、Codex CLI、Gemini CLI、Cursor；但真正经久不变、值得你带走的，不是某个产品，而是**项目运行框架、保存下来的规则、技能与工作手册、子智能体、远程/HPC 工作流、同伦工作流，以及验证纪律**。我们会拆开一次"第一次会话"的底层机制，讲清五支柱工作流如何落到文件上，端到端追踪一次 Aiyagari 求解，最后正视它的失败模式、安全红线和"上下文困境"。上一讲（Lec08）我们讲检索增强生成，把检索当成智能体众多工具中的一种；这一讲把"工具调用"放进一个会循环、会验证的控制回路里；下一讲（Lec10）我们就用四个真实案例把今天的工作流逻辑跑一遍。

## 学习目标

- 能解释终端智能体的"运行框架(harness)—大语言模型—本地文件"三件套，以及"模型输出 JSON 工具调用 → 运行框架执行 → 工具结果 → 下一轮"这个控制回路
- 能搭建并执行一个最小可用的 Git 安全工作流，说清为什么 Git 是智能体实验的"撤销键"与审计轨迹(audit trail)
- 能用同伦(homotopy)工作流把一个复杂研究任务拆成 V0 → V1 → V2 的逐级验证阶梯
- 能用文件搭起一个最小项目运行框架：CLAUDE.md、settings.json、rules、skills、子智能体(sub-agent)、hooks，并说清它们各自的加载时机与生命周期
- 能端到端追踪一次 Aiyagari 求解在运行框架里的文件流与编排循环
- 能识别智能体的常见失败模式（聚类标准误、顺利路径失败、长上下文漂移）、安全红线，以及"上下文困境"，并据此安排人类的外部审稿
- 能用六条标准（可复现、可验证、可审计、成本、速度、技能投资）判断一个 AI 辅助产物是否达到"研究级"

## Topic 1：Lec09_T1_Framing_Setup（共 17 张）

### 幻灯片 1：Topic 9.1 Agenda（本节路线图）
这一节我们讲三件事。第一，**立框架（Framing）**——到底什么叫智能体式 AI，它的"自主程度"是个光谱。第二，**智能体怎么调用工具**——底层其实就是一串 JSON 工具调用。第三，**搭台子（Setup）**——用 Git 把工作流变成可撤销、可审计的"耐用基础设施"。最下面这一行是整讲的主线图，请大家记住这条弧线：T1 立框架 → T2 拆引擎盖 → T3 同伦工作流 → T4 项目组织 → T5 失败与上下文困境 → T6 收尾。今天我们就站在这条线的最左端。

### 幻灯片 2：Why Economists Should Care（经济学家为什么要在意）
进入第一部分之前，屏幕上先闪过一张分节页，大字写着"Framing——从聊天工具到耐用的研究工作流"。好，先回答最现实的问题：这跟我做研究有什么关系？这一张的主旨用一句话概括就是——**应用研究真正的瓶颈，往往不是想法，而是执行。** 大家想想，把一个好问题变成干净的代码、诊断、表格和图，这个过程很慢；而且研究里有大量重复劳动：重整数据、重跑设定、追溯来源、重构脚本、更新图。智能体工具的价值，就是**压缩"从想法到第一个站得住脚的结果"之间的时间**。这反过来抬高了经济学家独有技能的回报：问题设计、制度知识、验证和判断。所以请大家不要误读——这一讲的承诺**不是"AI 替你做研究"**，而是：在一个仍然由你来定义、由你来辩护的问题周围，让实现更快、迭代更快。

### 幻灯片 3：Four Research Patterns（四种研究范式）
这张表把今天会反复出现的四种研究范式先摆出来，左中右三列分别是"范式、代表任务、用错工作流的主要风险"。第一种，**可复用技能**，比如做裁判式的论文评审，风险是评语泛泛、引文是幻觉、没有质量闸门。第二种，**实证流水线**，比如把 MEPS 数据做协调并出图，风险是对照表用错、调查权重被丢、验证悄悄失败。第三种，**公开网络数据集**，比如带字段级溯源的学者名录，风险是来源不可靠、缺失被藏起来、没有审计线索。第四种，**全生命周期协作者**，从研究备忘录到流水线到批评再到修订，风险是产出很光鲜，底子却是站不住的框架或松垮的论据纪律。这一整讲讲的是**终端智能体工作流**：Claude Code、Codex CLI、Gemini CLI、Aider、Cursor 都只是例子，经久的功课是经济学家怎么组织文件、工具、验证和判断。最后一句给上一讲做个接口：智能体式 RAG 和单次 RAG 不同——是否检索、何时检索，由智能体**动态地**通过同一套 JSON 工具调用机制来决定；检索只是它能组合的众多工具之一，旁边还有代码执行、文件读写、网页抓取。

### 幻灯片 4：What Remains Human Across the Four Patterns（四种范式里，哪些仍归人类）
这张分两栏，左边是"仍然由你掌管的"，右边是"智能体来加速的"，对照着看最清楚。左边：研究问题、成功标准、编码与来源规则、验证目标、最终解释——这些都姓"你"。右边：重复执行、文件处理与重构、可提示的任务分解、修好之后重跑、初稿诊断与报告——这些交给智能体。我给经济学背景的同学点一句这张的落脚点：好处**不是判断消失了**，而是**有纪律的执行变便宜了**。换句话说，智能体不是替你思考，而是把你思考的成本结构改了——省下来的时间，应该重新投到左边那一栏。

### 幻灯片 5：What Modern Web Chat Already Does Well（现代网页版聊天已经能做好什么）
这一张是为了把"基准"摆正。截至 2026 年 4 月，一个强的网页版聊天产品，对经济学家其实**已经很有用**了：帮你头脑风暴模型设定、实证策略、评审量规、稳健性检查；总结论文、裁判报告、讲义；查看你上传的文件、解释代码片段；有时还能浏览网页或在沙箱里跑些受限的工具；甚至能在你打开编辑器之前先帮你起草一份规格说明。所以请大家注意——我们今天要对比的**弱基准，不是"浏览器什么都做不了"**，而是"一次性的聊天会话、背后没有一个耐用的运行框架"。把这个基准定准了，下一张我们才能讲清楚：到底是哪一块在没有项目运行框架时会塌。

### 幻灯片 6：What Still Breaks Without a Project Harness（没有项目运行框架时，还会在哪里塌）
接着上一张，这里列出一次性聊天会话最容易塌的四个点，而且偏偏塌在研究项目"动真格"的地方。第一，**耐用的上下文很弱**：昨天定的约定、做的更正，今天不一定可靠地嵌进工作里。第二，**可复用的工作流很弱**：你的验证清单活在提示词里，而不是活在可检视的文件里。第三，**受控的执行很弱**：模型并没有真的在你的项目目录里、用你真实的脚本和输出在跑。第四，**审计轨迹与溯源很弱**：很难回看到底是哪些文件、命令、检查、来源产出了这个结果。所以真正的对比是这样的——**智能体有用，不是因为它"更聪明"**，而是因为它能在一个有文件、有工具、有可重复工作流的结构化项目里干活。

### 幻灯片 7：What Makes a Workflow Agentic Under the Hood?（底层看，什么让工作流"有智能体性"）
这一张中间是一条从左到右的控制回路示意图，我讲的时候会用激光笔顺着箭头点一遍。最左是"用户目标 + 成功标准"，往右是"编排器或规划器"，再往右是"工具：shell、Python、网页",再到"项目文件 + 记忆"，再到"验证器或评估器"，最右产出"产物 + 报告"。这条线要传达一个核心信息：**智能体工作流不只是文本生成，而是围着工具、文件、检查器套了一个控制回路。** 图下面我专门挑三个部件强调：**编排器(orchestrator)**，就是那个决定下一步做什么的循环；**记忆**，是存在磁盘上的项目状态，不只是聊天记录；**验证器**，是测试、基准或评审检查，由它来判定产出能不能活下来。记住这三个词，后面 T4 把它们一个个落成文件。

### 幻灯片 8：How Agents Invoke Tools: JSON Schemas（智能体如何调用工具：JSON 模式）
这一张回答一个很多人好奇的底层问题：智能体到底怎么"动手"？接上 Lec07 T3a 我们讲过的——大语言模型可以靠"模式约束解码"吐出结构化的 JSON。在终端智能体里，**每一次工具调用走的都是这套机制**。看屏幕上这行 JSON：当智能体决定读一个文件，它就吐出一段 `{"tool": "Read", "args": {"file_path": "aiyagari_v0.py"}}`。这段我不逐字念语法，只讲它干什么：它在说"请调用 Read 工具、参数是这个文件路径"。运行框架把这段 JSON 解析出来、真的去执行 Read、再把文件内容当作下一条消息喂回去；智能体读到结果，再决定下一步。这就形成一个**回路**：模型输出 JSON → 运行框架执行 → 工具结果 → 下一轮模型，一直到模型发出"完成"信号或撞到停止条件。这里有四个要点：第一，**模式就是契约**——每个工具公布自己的参数模式，不符合模式的输出会被拒掉。第二，**同一个大脑**——没有一个单独的"规划器"，写代码的和决定调工具的，是同一个 Transformer。第三个关键含义最深刻：**智能体的每一个动作，本质上都是一次被工具模式约束的下一个词元预测。**

### 幻灯片 9：How Should Economists Evaluate an Agentic Workflow?（经济学家该怎么评估一个智能体工作流）
这张表给出五条评估准则，左列是准则、右列是你该问的问题，我建议大家把它当成一张随身清单。**正确性**：它算的、抽的、总结的，是不是那个对的对象？**可复现性**：从保存的文件和规则出发，一次全新的运行能不能复刻出同一个产物？**可审计性**：你能不能检视产出这个结果的命令、检查和来源线索？**隐私边界**：哪些文件留在本地，哪些内容其实仍会穿过网络？**延迟/成本**：省下的墙钟时间，值不值这些词元、调试和监督的代价？我给经济学的同学点一句这张的态度：**一个炫的演示是不够的——研究工作流必须是可检查、可辩护的。** 这五条会在 T6 收尾时再升级成六条更正式的判据。

### 幻灯片 10：What Makes Something "Agentic"? Four Features（什么才算"智能体"？四个特征）
这一张把"智能体性"拆成四个累加的特征，请大家注意是**累加**，缺一不可。第一，**工具使用(tool use)**——它会调用 pandas、curl、R、statsmodels、shell，任务需要什么就调什么。第二，**自主性(autonomy)**——它能规划一个多步实证工作流，不用你一步步催，比如"下载 FRED → 清洗 → 回归 → 画图 → 存表"作为一条命令一气呵成。第三，**迭代(iteration)**——它看到回归失败、定位到那一列坏数据、改公式、再重跑。第四，**持久性(persistence)**——它跨会话记住你的项目约定：变量命名、偏好的包、验证过的基准。最后一句很重要：**这四点是累加的。** 只有工具使用、没有自主性，那不过是个花哨的 Python 交互窗口；有自主性、没有迭代，那是一个一遇错就死的脚本。四个都齐了，才配叫"智能体"。

### 幻灯片 11：Spectrum: Chat, IDE Assistant, Terminal Agent（光谱：聊天、IDE 助手、终端智能体）
这张表把三类工具横着摆开比较，按"最擅长、上下文、典型角色、经济学例子"四行来看。**网页聊天**：最擅长思考和起草，上下文是对话加上传文件，角色像"架构师的白板"，对应"设计识别策略"。**IDE 助手**：最擅长改本地代码，上下文是你打开的文件，角色像"编码副驾",对应"清理一个回归文件"。**终端智能体**：最擅长端到端执行，上下文是整棵项目树，角色是"工作流操作员",对应"跑完整条流水线"。今天的具体例子是 Claude Code；但请记住一般性的功课——同一套工作流逻辑也出现在 Codex CLI、Gemini CLI、Aider 这些终端智能体工具里。工具会换，逻辑不变。

### 幻灯片 12：The Bridge: How a Chatbox Becomes a Terminal Agent（桥梁：聊天框如何变成终端智能体）
这一张讲清楚那个"开关"到底是什么。一个关键的技术变化是：2023 年之后的现代大语言模型支持**结构化工具调用**。模型不再写一句"你应该去跑 `python solve.py`"给人看，而是吐出一段机器可读的请求，就像屏幕上这行 `{ "tool": "Bash", "command": "python aiyagari_v0.py" }`。然后一个装在你 Mac 上的**运行框架(harness)** 真的去执行它、把真实输出返回；模型读到输出、再决定下一步——**就是这个回路让东西变得"有智能体性"。** 下面这张小表对比 claude.ai 浏览器版和终端版 Claude Code：两者用的 LLM 模型是同一个（比如 2025 年 11 月的 Opus 4.5）；区别在运行框架——浏览器版没有运行框架、是沙箱，终端版是你 Mac 上的本地 CLI；浏览器版不能跑 Python，终端版能跑**你的** Python、在**你的**机器上；浏览器版看不到真实报错，终端版看得到、还会自动回环。一句话收尾：**同一个大脑，装了不同的胳膊。** 终端智能体不是一个魔法般更聪明的模型，是运行框架把开关从"只能出文本"拨到了"在项目里又出文本又动手"。

### 幻灯片 13：Early Demo: From Prompt to Research Artifact（早期演示：从提示词到研究产物）
这一张用一个具体例子把抽象的"工作流"落地，左右两栏连起来读。运行的例子是一个 MEPS 试点，问题是："用调查权重，建一个 2012 到 2014、按年龄组划分的未参保面板。"左栏前三步：第一步**提示词**，把问题、权重、想要的输出定义清楚；第二步**计划**，列出要下载、协调、验证哪些文件；第三步**运行**，解析原始文件、映射各年特有的变量、算出加权率。右栏后两步：第四步**验证**，把 2013 年和一个外部基准对照、检查权重变量、保存对照表；第五步**输出**，一张图、一个 CSV、一段简短说明，写清什么通过了、什么还不确定。右下角还提醒一句：**同一个回路、不同的产物**——论文评审变成结构化批评，学者数据集变成带溯源的 CSV，Aiyagari 模型变成对过基准的求解器输出。为什么这么早就给大家看这个？因为**先把工作流变具体，再去给支撑它的项目对象起名字**，会好懂得多。

### 幻灯片 14：What Belongs in the Main Deck vs. the Appendix（哪些进正文、哪些进附录）
这里屏幕上又过一张分节页，写着"Setup——设置里那些耐用的部分：Git、项目文件夹、审计轨迹"。好，进入第二部分。这一张讲一个很实用的取舍：两类设置建议"老化速度"完全不同。一类是**有时效、依赖具体工具的**——安装命令、包名、订阅档位、模型 ID、定价，这些每几个月就变，应该塞到本讲最后的附录(T6)里去。另一类是**耐用、概念层面的**——版本控制、项目文件夹布局、文件驱动的工作流、审计轨迹，这些扛得过每一次工具更替，所以放在正文这里讲。我给大家一条很好用的判别法则：**如果某张幻灯片在你从 Claude Code 换到 Codex CLI 再换到 Gemini CLI 时需要重写，那它就是操作性的，不是概念性的。**

### 幻灯片 15：Why Git, Not OneDrive or Dropbox（为什么用 Git，而不是 OneDrive 或 Dropbox）
这一张分两栏对照：左边是"不用 Git 的风险"，右边是"Git 给你什么"。先看左边——Claude Code 一次会话能自主改几十个文件；而 OneDrive、Dropbox 是靠**复制**来同步的，两处同时写就会产生损坏的冲突文件；更要命的是没有撤销：智能体改坏了，没有 Git 就没有"还原";也没有审计轨迹，你看不到什么时候改了什么。再看右边——`git diff` 在你接受之前就把智能体改了什么一字不差地摆给你看；`git checkout -- .` 瞬间撤销所有未提交的改动，这是你的**紧急刹车**；`git log` 把每次改动连同时间戳和说明都记下来；而且它离线就能用，云同步反而会和智能体飞快的写文件"抢车道"。这里我点一句特别要小心的常见误区，也是这张的落脚法则：**大数据文件放 OneDrive，代码和脚本放 Git，千万别用同一个工具同时管这两样。**

### 幻灯片 16：First Git Setup: Three Minutes（第一次 Git 设置：三分钟）
这一张是上机操作，左右两栏的代码我不逐行念语法，只讲它们各自干什么。左上**一次性的全局设置**：两行 `git config --global` 把你的名字和邮箱告诉 Git，以后所有项目都用这套身份。左下**每个项目的设置**：`cd` 进项目目录、`git init` 建仓库、用一行把 `data/`、`output/`、`*.pdf` 写进 `.gitignore`（意思是这些大文件别纳入版本管理），再 `git add` 和 `git commit` 做第一次提交。右栏是**唯一一条规矩**：每次智能体会话**之前**提交一次，验证完结果**之后**再提交一次——这就足够安全地开工了。右下角再给一次紧急刹车：`git checkout -- .` 瞬间撤销所有未提交的文件改动，是智能体跑偏时的安全网。最后宽慰大家一句：**你不需要把 Git 学得多深**——`git add -A`、`git commit -m "..."`，外加一个和导师约好的、非破坏性的还原流程，三招就够你安全地和终端智能体共事了。

### 幻灯片 17：Looking Ahead: T2 Opens the Hood（前瞻：T2 打开引擎盖）
这一张收一下 T1。T1 把问题立住了：光聊天不够，要有一个运行框架，把工具、文件、验证器包在模型外面，这个回路才能干真活。具体来说——**T1 告诉你智能体"做什么"、运行框架"为什么存在"**；接下来 **T2 会告诉你运行框架"怎么工作"**：有哪些部件、文件层级长什么样、怎么初始化、权限怎么管、推荐的第一次会话怎么走。再往后 T3 引入同伦工作流，给这个运行框架一件有纪律的事去做。请大家记住底部这条主线弧——我们刚走完最左边的 T1 立框架，下一站就是 T2 拆引擎盖。

## Topic 2：Lec09_T1b_Agentic_Landscape（共 16 张）

> 衔接语（标题页）：这一块的标题页写着"Lecture 9.1b: The Agentic-AI Landscape (mid-2026)"。T1 我们把镜头对准了"终端智能体"这一条主干；这一段是个插曲，把镜头拉远，让大家看清楚一个经济学家如今身处其中的、更大的智能体式 AI 全景。这一块事实很密、日期很多，我提醒大家：**重点不是背年份，而是学会用"测量效度"的眼光去看这些数字。**

### 幻灯片 1：Topic 9.1b Agenda（本节路线图）
这一节我把全景拆成六块快速走一遍。第一，**互操作性栈**——MCP、A2A、AGNTCY/ACP，以及中立治理。第二，**编排模式**——各种框架、上下文工程、多智能体的成本-收益。第三，**推理模型与推理时算力**——思考预算、被实测出来的"任务时长"。第四，**自主编码与计算机操作智能体**——定时运行时、沙箱。第五，**基准与测量效度**——呼应整门课的"测量"主题。第六，**安全与可复现**——不可信输入、证据链。这里有一个很重要的阅读约定，请大家记在心里：标着 **[solid]** 的是一手的、可引用的；标着 **[hype]** 的是厂商自报的（我会给出反向来源）。还有一句话：所有事实截至 2026 年 6 月，这个领域每个月都在变，**讲之前请重新核对。**

### 幻灯片 2：Three Layers of Agent Interoperability（智能体互操作的三层）
进入第一块前，屏幕上有张分节页："互操作性栈——在模型上竞争，在管道上合作。"这一张的大主旨就是这句话：2025 到 2026 年的故事是"立标准"——各家厂商在模型上拼,却越来越多地在"智能体与工具之间的接线"上合作。看这张三层表。最上层是**智能体↔工具**，协议是 **MCP（Model Context Protocol，模型上下文协议）**，它标准化的是"智能体如何发现并调用外部工具和数据源"。中间层是**智能体↔智能体**，协议是 **A2A（Agent-to-Agent，智能体间协议）**，标准化"独立的智能体如何互相委派任务"。底层是**发现与身份**，叫 **AGNTCY / ACP**，管的是智能体目录、能力名片、身份和信任。表下面三条事实都是 [solid]：MCP 由 Anthropic 在 2024 年 11 月提出，现在已经是**多厂商**的、不再私有；OpenAI 在 2025 年 10 月 6 日的 DevDay 上采纳了 MCP，Google、Microsoft 的工具链也支持；治理还搬进了一个中立的家——2025 年 12 月 9 日成立的 Linux 基金会"智能体 AI 基金会(AAIF)"如今托管着 MCP 和相关项目。

### 幻灯片 3：Why Neutral Governance Is a Network-Effects Story（为什么中立治理是一个网络效应故事）
这一张是专门留给经济学家的——互操作性栈是一个教科书级的**标准制定 / 网络效应**案例。我顺着四条讲：第一，一个共享协议**降低转换成本**——一个工具用 MCP 包一次，就能在 Claude、ChatGPT、Gemini 和开源智能体上通用。第二，**网络效应**让标准随采用增长而更值钱——这正是单厂商协议会遭遇采用阻力的原因。第三，把 MCP 搬到中立的 Linux 基金会 AAIF 之下，是一步经典棋：把"管道"交给中立机构，对手才愿意在上面建东西。第四，竞争于是集中到还有租金的地方——模型质量、延迟、价格，而不是连接器。下面这个绿色的 takeawaybox，我用"这一段一句话记住"的口吻读：**协议是有版本的。** 把你用的**规范版本**（比如 MCP 规范的日期、A2A 的版本号）连同模型版本和日期一起钉死——同一个工具调用，在不同的规范修订下行为可能不一样。这一点正好预告了整讲反复出现的"钉版本"纪律。

### 幻灯片 4：Four Orchestration Patterns（四种编排模式）
这里又过一张分节页："编排模式——多步智能体系统实际上是怎么搭起来的。"这一张告诉你：生产级的智能体系统，是由一小撮反复出现的控制结构搭出来的。看这张表的四种模式。**编排器-工作者**：一个主智能体拆解任务、分派给若干工人——这是**生产环境里的主流**。**规划器-执行器**：一个部件做规划，另一个一步步执行。**反思(reflection)**：智能体在返回之前，先批评、再修订自己的输出。**交接(handoff)**：控制权在专职智能体之间传递，比如先分诊再转给专家。最后这句话很关键，请大家把它和 T1 的图接起来：**你在 T1 到 T5 学的那套终端智能体工作流，本身就是一个编排器-工作者系统**——主智能体做编排，code-reviewer、domain-reviewer、verifier 这些子智能体就是工人。全景只是在同一个回路外面，加了词汇和工具而已。

### 幻灯片 5：Frameworks Reached 1.0 (2025–26)（编排框架在 2025–26 年迈入 1.0）
这张表说明：编排这一层，已经从研究演示成熟成了有版本号、有支持的框架。我快速读一遍这张"框架—里程碑—厂商"表：LangGraph 1.0，2025 年 10 月，LangChain；OpenAI Agents SDK 加上 AgentKit，SDK 是 2025 年 3 月；Google 的 Agent Development Kit，v1.0 在 2025 年 5 月；Microsoft Agent Framework，1.0 在 2026 年 4 月；CrewAI 的 1.0；以及 Anthropic 的 **Claude Agent SDK**，2025 年 9 月。表下有个命名注记，标 [solid]：原来叫 Claude Code SDK 的，在 2025 年 9 月 29 日改名为 **Claude Agent SDK**，反映它已经泛化到编码之外。这一张的**耐用功课**是：**模式比框架活得久。** 把编排器-工作者学透一次，再把它映射到你所在机构采用的那个 SDK 上就行——别被框架名字牵着走。

### 幻灯片 6：The Multi-Agent Cost–Benefit Decision（多智能体的成本-收益决策）
这一张左右两栏，讲一个经济学家最该有感觉的判断：**多上几个智能体不是免费的，要当成边际价值对边际成本来算。** 左栏：Anthropic 报告，它的多智能体研究系统在内部的研究评测上，比单智能体基准高出 **+90.2%**……但代价是大约 **15 倍的词元成本**。所以结论是——当任务是宽的、可并行的、而且答案的价值相对于词元很高时，多智能体才划算；对窄的、顺序的、便宜的任务，它就是浪费。左栏下面那行小字提醒我们保持清醒，标 [solid, Anthropic-internal-eval]：这是厂商在自己定义的研究任务上的基准，不是外部套件，**那个 +90.2% 只能当方向，不能当可移植的数值。** 右栏的 takeawaybox 我用经济学口吻读：**你是在选一个点，让边际研究价值等于边际词元（以及延迟、调试）成本。** T4 里那个 Aiyagari 的子智能体评审，正当性来自**省墙钟时间**，而不是因为"智能体越多越好"。

### 幻灯片 7：Context Engineering Displaced Prompt Engineering（上下文工程取代了提示词工程）
这一张点出 2025–26 的一个范式转变：**管理"上下文窗口里装了什么"，如今比"措辞一个聪明的提示词"更重要。** 三条手段。第一，**压缩(compaction)**：把陈旧的对话轮次总结并清掉，让工作集留在窗口里高召回的那一段——这正是 Lec07 T3b 讲过的"迷失在中间(lost in the middle)"问题。第二，**外部记忆**：把状态持久化到文件里，比如 `NOTES.md`、`progress.md`、`CLAUDE.md`，别指望聊天记录。第三，**给子智能体干净的上下文窗口**：交给工人一份新鲜、聚焦的上下文，而不是编排器那一堆累积的噪声。最后一句给我们撑腰——为什么这跟研究有关：**这恰恰就是 T4 到 T5 已经教过的那套纪律**——文件驱动的工作流、进度日志、聚焦的审查员。全景只是给这套习惯起了个名字，习惯本身早就是对的。

### 幻灯片 8：Reasoning Models and Think-Budget Control（推理模型与思考预算控制）
这里过一张分节页："推理模型——把工具用进推理回路，以及智能体到底能跑多久。"这一张讲前沿模型的两件新事：它们现在会花**可变的推理时算力**，而且越来越多地把工具调用放进**推理回路内部**。四条 [solid] 事实快速读：第一，**回路内用工具**——OpenAI 的 o3 / o4-mini（2025 年 4 月）把工具调用和思考链交织起来，而不是先想完再动手。第二，**思考预算路由器**——GPT-5（2025 年 8 月）到 GPT-5.5（2026 年 4 月），按每条查询在快、深两种模式间路由。第三，**可开关的扩展思考加可配置的词元预算**——Claude Opus 4.5（2025 年 11 月）让你开关扩展思考、给思考词元设上限；它是第一个在 SWE-bench Verified 上越过 **80%** 的模型，且 Opus 定价降到每百万词元 5 美元/25 美元（输入/输出）。第四，**并行深度推理**——Gemini 的"Deep Think"并行探索多条推理路径。下面这个黄色 cautionbox 必须特别小心，请大家把这条警告带到任何地方：那个 80% 的 SWE-bench Verified 是真的，但这个指标已经被污染/饱和了——OpenAI 在 2026 年 2 月**停止上报** SWE-bench Verified。任何 Verified 的头条数字，都要配上 SWE-bench Pro（前沿水平约 55–59%，题目是留出来没见过的）一起看。

### 幻灯片 9：How Long Can an Agent Actually Work? Measure, Don't Trust Marketing（智能体到底能干多久？去测量，别信营销）
这一张左右两栏，主旨一句话：厂商说"能干几小时""能跑好几天"，METR 给了一个**实测的**替代品。左栏三条：第一，METR 的"任务时长翻倍"结果——一个智能体在 **50% 可靠性**下能完成的任务时长，大约每 **7 个月**翻一倍，到 2024–25 年加速到约 **4 个月**翻一倍，这条标 [solid]。第二，Time Horizon 1.1（2026 年 1 月）给出：Opus 4.5 约 **320 分钟**、GPT-5 约 **214 分钟**（都是 50% 可靠性下的时间跨度）。第三，用这些实测分钟数，去取代厂商口中的"多小时/多天自主"。右栏的 cautionbox 我提醒一句指标的脆弱性：这个数字绑在 **50% 可靠性**阈值和一个特定任务套件上；换到 80% 可靠性，这个时间跨度会短得多，而且换套件就漂。一个"实测但脆弱"的数字，仍然胜过一个厂商口号——下面 [hype] 反例就是那些写着"多小时""多天"自主、却根本不说可靠性阈值的产品页。底部把这翻译成研究的问法：对的问题不是"它能跑几小时？"，而是"在什么可靠性下、在什么任务分布上、用什么方式验证？"

### 幻灯片 10：Coding Agents Became Scheduled, Autonomous Runtimes（编码智能体变成了定时、自主的运行时）
又一张分节页："自主编码与计算机操作——从交互式助手，到定时、沙箱化的运行时。"这一张讲 2025–26 年编码智能体的一个转身：从交互式助手，变成有持久状态的后台运行时。两条 [solid]：第一，**OpenAI Codex 的"Goal Mode"** 在 2026 年 5 月成了默认，带跨会话的持久状态——智能体是去"续上一个目标"，而不是每次聊天从零开始。第二，**Anthropic 的"Code with Claude"（2026 年 5 月 6 日）** 把 Claude Code 重新定位成一个**编排器**，配套四样东西：带提示词注入/破坏性动作分类器加人工批准闸门的 **Auto Mode**；由 cron 或 webhook 触发的 **Routines（例行任务）**；用于并行分支的 **Worktrees（工作树）**；以及带受限凭据的沙箱化 **Managed Agents**。底部这个 takeawaybox 是给研究基础设施的功课，我重读一遍：**在智能体无人值守地跑真实数据或代码仓库之前，先把沙箱、凭据范围、批准闸门配好。"自主"是一个权限决策，不是一个模型能力。** 这句话请记牢，T4、T5 我们会反复回到它。

### 幻灯片 11：Computer-Use Agents: Strong Benchmarks, Volatile Products（计算机操作智能体：基准漂亮，产品易变）
这一张讲浏览器/计算机操作智能体：纸面上变强了，但独立产品很动荡。两条事实：操作类智能体在 OSWorld-Verified 上达到约 **78–84%**（人类基线约 72%）；但独立产品很易变——Google 在 2026 年 5 月**砍掉**了 Project Mariner，OpenAI 把 Operator 并进了 ChatGPT Agent / Atlas。下面的 cautionbox 要小心：那些 OSWorld 分数**严重依赖脚手架、而且多半是自报的**——同一个模型换个运行框架分数差很多，"高于人类基线"也不代表它在**你那条没见过的**工作流上可靠，**只能当方向**。这里标注得很细：产品确实在churn 是 [solid]，但基准数字依赖厂商/脚手架。落脚的功课是：**别把耐用的研究基础设施，建在某一个实验性产品上。** 建在协议层（MCP）和你自己的文件上，把任何单一的浏览器智能体都当成可替换件。

### 幻灯片 12：SWE-bench Verified Collapsed Under Scrutiny（SWE-bench Verified 在审视下崩了）
这里又一张分节页："基准与测量效度——把这门课的测量主题，对准智能体评测。"这一张其实就是整门课"测量"主题打在智能体评测上的一句话：**一个头条数字，在你知道它的效度之前，还算不上一次测量。** 四条 [solid]：第一，**污染加上"刷脚手架"**的批评侵蚀了 SWE-bench Verified，OpenAI 在 2026 年 2 月停止上报它。第二，伯克利 RDI 在 2026 年 4 月**通过运行框架轻松攻破了四个智能体基准**——利用脚手架，而不是真去解题。第三，**永远要**把 Verified 头条配上 Scale 的 **SWE-bench Pro**（前沿约 55–59%，题目留出来没见过）。第四，对无人值守的用途，**重复下的可靠性**比 best-of-n 更重要：τ-bench 的 pass-hat-k 从单次约 90% 掉到 k=8 时的约 57%。底部的 cautionbox 给一条硬规矩：**永远别把一个 SWE-bench Verified 分数和一个 SWE-bench Pro 分数画在同一根坐标轴上**——题集不同、难度不同、污染暴露不同。

### 幻灯片 13：Single-Try Score vs. Reliability Under Repetition（单次得分 vs. 重复下的可靠性）
这一张左右对照，主旨是：对一个无人值守地跑的智能体，相关的统计量不是它**最好**那一次，而是它**每一次**都成不成。左栏"best-of-n 思路（对自主场景是错的）"：报告若干次尝试里最好的一次，会美化模型，只适合那种你事后会亲自检查的"人在回路"草稿。右栏"pass-hat-k / 可靠性（对自主场景才对）"：算的是 k 次独立运行**全部**成功的概率，τ-bench 从 k=1 的约 90% 掉到 k=8 的约 57%——当没有人逐次检查时，这个才是要紧的。底部我给一个经济学翻译，请大家细品：一个无人值守、每晚拉一次数据的智能体，就是一串重复试验；单次 90% 的成功率，复合到一个季度的夜间运行里，就会**频繁失败**。所以要**对着可靠性曲线设计，而不是对着演示设计。**

### 幻灯片 14：Treat Everything the Agent Reads as Untrusted（把智能体读到的一切都当成不可信）
这里过最后一张分节页："安全与可复现——智能体研究的不可信输入与证据链。"这一张点名智能体安全的标志性失败：**提示词注入(prompt injection)——智能体仅仅"读到"的数据，可以劫持它"去做"什么。** 三条：第一，**OWASP 的"智能体应用十大风险"**（2025 年 12 月）已经把这些风险编入规范。第二，有记录的真实漏洞：**EchoLeak**（CVE-2025-32711，零点击的 M365 Copilot 数据外泄）、Claude Chrome 扩展里的 **ShadowPrompt**、以及 Anthropic 的 **GTG-1002**——首次基本自主的网络攻击（2025 年 11 月）。第三，**NIST CAISI** 的红队测试，用自适应攻击把"任务劫持"成功率从 **11% 抬到了 81%**。下面的 cautionbox 是一条操作规矩，标 [solid]：**把智能体读到的任何内容——邮件、网页、检索到的文档、甚至工具说明——都当成一个不可信的注入通道。** 用最小权限沙箱和可撤销的权限，正如 T4 里 settings.json 的 deny 列表、T5 的安全那一张所规定的。

### 幻灯片 15：Reproducibility: Chain-of-Custody for Agentic Results（可复现：给智能体结果建证据链）
这一张问一个很硬的问题：智能体能不能复现一个已发表的计算结果？答案往往是**只能部分复现**——这恰恰让"记录日志"变成不可商量的。两条：第一，**CORE-Bench** 显示，智能体复现已发表计算结果的成功率只有约 **60%（简单）/ 21%（难）**，标 [solid]。第二，所以必须**记录完整的轨迹**：提示词、工具调用、随机种子、**模型版本**、**规范版本**、**日期**——这就是任何智能体产物的证据链。下面的 cautionbox 提醒大家**带着怀疑读厂商的安全数字**：要分清厂商说的"在一个**固定**套件上约 1% 攻击成功"和学术界发现的"**自适应**攻击仍超过约 85%"——一个固定套件的数字，测的是那个套件，不是威胁模型本身。底部把它接回 T6：这就是同一套六条判据的纪律（可复现、可验证、可审计），只是现在多了全景逼你去钉死的日期和规范版本。

### 幻灯片 16：Synthesis: The Landscape Reinforces the Workflow Spine（综合：全景在强化工作流主干）
这是本块的收束页，没有分节页，直接综合。主旨：上面每一块，都映射回 T1 到 T6 的终端智能体工作流，也映射回整门课"测量/识别"的主题。我顺着这张表读一遍这种映射：**互操作性(MCP/A2A)**——建在中立协议层上、别绑一个产品，钉死规范版本；**编排**——T4 的子智能体评审本身就是编排器-工作者，只在价值大于词元成本时才为多智能体买单；**推理与时间跨度**——把"能跑几小时"换成一个有可靠性阈值的实测数字；**编码/计算机操作**——自主是一个沙箱加批准闸门的决策，要在运行前就定好；**基准**——一个头条分数在你知道其效度之前不算测量（Verified 对 Pro）；**安全与可复现**——不可信输入纪律，加上记录在案的证据链（日期、版本、种子）。最后用屏幕中央这句话收尾，也请大家记住整讲的态度：**管道每个月都在变，研究纪律不变。在问题和判断上竞争，在标准上合作，先测量再信任。**

### 幻灯片 3：Terminal Vocabulary for Economists（给经济学家的终端词汇）
进入第二部分前，屏幕上有张分节页："拆引擎盖——运行框架、记忆、权限和控制回路。"很多经济学背景的同学对终端犯怵，所以这一张先把五个最基本的词讲清楚。**Terminal（终端）**：你敲命令、而不是点按钮的那个文本窗口。**Shell**：解释命令的程序，macOS 常用 zsh，很多例子写成 bash。**Bash**：一种常见的 shell 语言——当 Claude Code 说它要用 Bash，意思就是"在终端里跑这条命令"。**Working directory（工作目录）**：命令从哪个文件夹运行，`cd my-project` 改它、`pwd` 打印它。**PATH**：你敲 `python` 或 `claude` 时，shell 去搜索的那一串文件夹。为什么这要紧？因为**终端智能体是通过 shell 命令来行动的**——如果工作目录或 PATH 不对，智能体本身很能干，却在错误的地方干活。

### 幻灯片 4：Three Components of a Terminal-Agent Setup（终端智能体的三个部件）
这一张左文右图，把终端智能体拆成三个**物理上分开**的部分，请大家务必记牢这个划分。第一，**运行框架(harness)**——住在你的 Mac 上，是你安装的 CLI 软件，负责读文件、跑 shell 命令、管理对话循环。第二，**大语言模型(LLM)**——住在服务商的服务器上，每条消息都连同对话历史一起经 HTTPS 发到 API，"思考"发生在云端。第三，**你的文件**——也住在你的 Mac 上，Python 脚本、数据 CSV、LaTeX 全在你磁盘上，代码用你的硬件、你的包来跑。右边的小图就两个框：上面蓝框是"运行框架 + 文件（你的 Mac）"，下面橙框是"LLM（Anthropic API）"，两条弯箭头来回——上行送"提示词 + 上下文"，下行回"工具调用 + 文本"。我把右下角那句话单独拎出来，因为它是下一张的引子：代码能在本地跑、很多项目文件留在本机，这**并不**自动等于整条工作流就是私密的。

### 幻灯片 5：Privacy Boundary: Local Execution Is Not the Same as Local Processing（隐私边界：本地执行不等于本地处理）
这一张专门掰开上一张那句话，因为它涉及合规红线。四点：代码可以在你机器上**本地执行**；很多项目文件可以**留在本地磁盘**；但是——如果文件内容、提示词、或工具输出被放回对话里发出去，**这些内容仍然会穿过网络**；只有一个完全本地、或机构私有的部署，才真正改变这条边界。这里我用"特别小心"的口吻强调落脚法则：**本地执行不是把受限数据粘进智能体工作流的许可证。** 给我们在中国、或在有数据合规要求的环境里工作的同学，这条尤其重要——能在本地跑代码，绝不意味着你可以把受保护的微观数据直接喂给一个走云端 API 的智能体。

### 幻灯片 6：The File Hierarchy: Global vs. Local（文件层级：全局 vs. 局部）
这一张是张路径表，核心一句话：**两层配置，局部覆盖全局。** 我不逐格念路径，讲清楚两层各管什么。上面一组是**全局**层，住在你主目录的 `~/.claude/` 下：`settings.json` 放默认权限和模型偏好，`MEMORY.md` 放跨项目的、永久持续的记忆，`skills/` 放每个项目都能用的技能——这些是你的"个人默认值，到处都生效"。下面一组是**局部**层，住在某个项目里：`CLAUDE.md` 是项目大脑、每次会话都读，`.claude/settings.json` 是项目权限、会覆盖全局，`.claude/skills/` 是这个项目的斜杠命令，`.claude/agents/` 是专职审查角色，`.claude/rules/` 是常开护栏。表下还有一句很重要的可移植性提醒：**别的智能体也走类似布局**——Codex CLI 用 `AGENTS.md`，Gemini CLI 用 `GEMINI.md`；"全局默认 + 项目专属系统提示"这个模式，跨产品都耐用。一句话记住：**全局点文件夹 = 你的个人默认（处处生效），局部点文件夹 = 这个项目的规则（只在这里生效）。**

### 幻灯片 7：Initialization: What Happens When You Type claude（初始化：你敲下 claude 那一刻发生了什么）
这一张讲一个很多人没意识到的事实：**在你打第一条消息之前，已经有五步跑完了。** 第一步，**读全局配置**——加载 `~/.claude/settings.json`：权限默认、模型偏好。第二步，**探测项目上下文**——在当前目录（和父目录）里找 `CLAUDE.md` 和 `.claude/`。第三步，**载入项目大脑**——把 `CLAUDE.md` 读进上下文窗口。第四步，**自动加载所有规则**——每个 `.claude/rules/*.md` 文件都被悄悄读进来。第五步，**就绪**——你还没开口，上下文窗口已经预先填好了。我喜欢这张的比喻：第四步就像一位老师上课前重读自己的讲义——学生进门时，上下文早就装好了。但请注意末尾这句**成本警告**：第三、四步在你打字之前就消耗了词元，所以**要把 CLAUDE.md 和规则文件写得精简**。

### 幻灯片 8：Tokens and Cost: Putting Cost on the Radar（词元与成本：把成本放上雷达）
这一张把"成本"正式摆上台面：**每一个智能体回合都是一次模型 API 调用，成本随输入和输出词元数缩放。** 四点。**输入词元**：你的提示词、对话历史、CLAUDE.md、规则、检索回来的分块——每一步往上下文里加东西，都在加成本。**输出词元**：生成的代码、JSON 工具调用、文字解释；重推理模式还会产生大量内部词元。**长会话会累积上下文**：用压缩命令（`/compact`、"总结并清空"）把窗口腾出来，用成本追踪（`/cost`）看到目前花了多少美元。**为可复现钉死参数**：记录模型版本、提示词模板、必要时记随机种子；AEA 在 2024 年 10 月的披露政策已经延伸到 AI 辅助的分析。底部一句定调，请大家记住：成本在 Lec07 T3a 有定价表，**这里要传达的是——成本是工作流的一个参数，不是脚注。**

### 幻灯片 9：The Permission System and Local Code Execution（权限系统与本地代码执行）
这一张左右两栏。左栏是 Claude 的"工具箱"小表：`Bash` 跑任意 shell 命令，`Read` 读文件，`Write` 创建或覆盖文件，`Grep/Glob` 搜内容/找文件，`Agent` 派生一个子 Claude 实例。右栏是权限模型，三档：**默认**——每次 Bash 调用前 Claude 都先问你，你能先看到那条确切的命令；**白名单**——把信得过的命令加进 `.claude/settings.json`，屏幕上这段配置我不逐行念，意思就是把 `Bash(python *)`、`Bash(git *)` 这类放进 allowedTools，以后这些就不再每次问；**跳过权限**——所有确认全免，只在你完全信任这个任务时才用。下面还回答了一个常见困惑——"刚才到底是哪个 Python 在跑？"：Claude 的 Bash 继承你 shell 的 `$PATH`，如果你在敲 `claude` 之前先 `conda activate myenv`，那么**那个**环境的 Python 才会跑；建议在 CLAUDE.md 里加一句 `which python` 的检查来确认。

### 幻灯片 10：Key Modes: Plan, Effort, and Session Control（关键模式：计划、推理强度、会话控制）
这一张是一张"命令速查表"，我挑要点讲。**Shift+Tab** 进**计划模式(plan mode)**：Claude 写出计划、但**不执行**，等你批准——**每一个非平凡任务都从这里开始**。**/effort max**：最大推理深度，质量最好但更慢更贵，留给新问题、留给经济学正确性吃紧的地方；**/effort default**：质量和速度平衡，用于日常。**/cost**：看本次会话用了多少词元、估算多少美元，长任务前先查一下预算。**Esc**：立刻打断 Claude——它跑偏时按它。**/compact**：把对话总结掉、腾出上下文窗口，约 20 轮后、或阶段之间用。**/clear**：清空上下文、从头开始，做不相关的新任务时用。底部点出**推理强度-成本的权衡**：最大推理加长上下文，可能比默认贵一个数量级；所以**把推理强度花在"决策"上，在"执行"上省着用。**

### 幻灯片 11：Your First Five Minutes: A Concrete Walkthrough（你的头五分钟：一个具体走查）

### 幻灯片 15：Pillar 1: Question Design（支柱 1：问题设计）

### 幻灯片 17：Pillars 3 and 4: Data/Numerical Discipline and Domain Constraints（支柱 3 与 4：数据/数值纪律与领域约束）
这一张一次讲两根柱子。**支柱 3——数据/数值纪律**：对模型，是网格设计、插值、冲击离散化、稳定性检查；对数据工作，是模式协调、权重、对照表、缺失、保存的来源日志；核心是**认得出失败模式**——扭折、被丢的权重、断掉的映射、悄悄变弱的来源。**支柱 4——领域约束**：进阶方法仍然要紧——投影、摄动、聚类决策、来源限制、论据纪律；关键是**知道智能体那个图省事的默认值，在什么时候是计算上、计量上、或实质上错的**。底部这句经济学要点请大家记住：**一个工作流可以跑得很干净，却仍然是错的。** 智能体降低的是编码成本，它**不会**消除逼近误差、数据脆弱性、或来源纪律上的问题。

### 幻灯片 18：Pillar 5: Code Literacy and Division of Labor（支柱 5：代码素养与分工）
这一张是一张分工对照表，左列"你提供"、右列"智能体提供"。我读成对比性的话：问题、识别逻辑、来源规则归你，快速生成和重构代码归它；工作流选择、基准设计归你，样板代码实现和调试归它；对数据、模型、制度的知识归你，文件编辑、脚本编写、测试运行归它；经济学解释、研讨会上的辩护归你，对可见错误和输出的迭代归它。底部这句口号是这一节的灵魂，请大家务必带走——研究版的说法是：**智能体可以是一个很强的研究助理(RA)，但你仍然得当那个首席研究者(PI)。**

## Topic 4：Lec09_T3_Homotopy_Tools（共 18 张）

> 衔接语（标题页）：标题页是"Lecture 9.3: The Homotopy Workflow and Tool Choice"。上一节我们看了运行框架的机制；这一节给它一件有纪律的事去做——同伦工作流：先建一个容易的版本、验证，再朝完整研究任务一步步延拓。这是整讲方法论的脊梁。

### 幻灯片 1：Topic 9.3 Agenda（本节路线图）
这一节三件事。第一，**同伦工作流**——迭代式精炼。第二，**OLG 五步演示**——一个做出来的实例。第三，**工具选择**——怎么挑工具和子智能体。底部主线弧告诉我们现在站在 T3 同伦这一站。我先把这一节的灵魂一句话剧透了：**先解一个有已知解的简单问题，再连续地形变到你真正想解的那个难问题。**

### 幻灯片 2：The Homotopy Workflow（同伦工作流）
进入第一部分前，屏幕上有张分节页："同伦工作流——从简单建到复杂，验证，再扩展。"这一张左文右图。先给定义：在工作流设计里，**同伦(homotopy)** 的意思是先解一个更容易的版本、再把它延拓向完整研究任务。左栏四条原则：从一个**有清晰直觉、有已知检查**的版本出发；把那个验证过的基线当成下一步的起点；新冒出来的 bug，就归到你刚加的那个新边际上；**别让智能体一跳就去解整个复杂问题**。右边的小图就是这套逻辑：V0 是确定性版，打勾后到 V1 加风险，再打勾绕到 V2 加分布，再打勾到 V3 加财政——**每一步都小、每一步都验证；某一步坏了，就退回上一个验证过的版本。** 中间那行公式其实是四个例子排成一条同样的逻辑链，我读出来：确定性模型 → 三年 MEPS 试点 → 单节评审 → 只放种子名单。底部点出为什么这对智能体编码特别有效：**当每一步都有边界、可测试、且接在一个已经能跑的基线上时，智能体表现最好。**

### 幻灯片 3：Homotopy in Practice: Build from Simple to Complex（同伦的实操：从简单建到复杂）
这一张顶上是一条六格流程图，我顺着箭头点一遍：1 设计 → 2 写规格 → 3 选算法 → 4 建 V0 → 5 验证 → 6 扩展。这条链要替换掉那句幻想式的提示词——"把我的项目解了"。下面三条把这条链的精神说透：从一个**你能陈述、能设基准**的问题开始；给智能体**有边界、有可见验收标准**的任务；**一次只加一个新成分**。我给大家点一句：很多人用智能体最大的失误，就是一上来就丢一个庞大模糊的目标过去；这条流程图就是治这个病的药。

### 幻灯片 4：Step 1: Design the Economic Problem（第 1 步：设计经济问题）
第一步：在任何代码之前，用经济学语言把任务写下来。五条：一句话的研究问题；目标和约束，或相关的来源规则；如果适用，写出均衡定义、被估量、或评审标准；参数、样本、来源全集、以及经济动机；你将当作证据的输出。屏幕中间是这一讲的**Aiyagari 锚点**公式，我把它念成话：家庭要最大化一生的期望贴现效用——也就是 E_0 对 t 从 0 到无穷、β 的 t 次方乘当期效用 u(c_t) 求和；约束是每期预算：当期消费 c_t 加下期资产 a_{t+1}，等于本息收入 (1+r)·a_t 加劳动收入 w·z_t；再加一条借贷约束，资产不能低于下限 a 下划线。底部提醒：同样的道理在别处也成立——一个模糊的 MEPS 任务书、模糊的评审请求、模糊的学者数据作业，都会产出"内部干净、实质却错"的东西。

### 幻灯片 5：Step 2: Write the Specification File（第 2 步：写规格文件）
第二步：**规格文件是你和智能体之间的契约。** 一个好的规格文件清楚地说明四件事：第一，假设和领域规则；第二，数据或来源限制；第三，流程和验证目标；第四，需要的输出、以及存到哪里。屏幕上举了几个例子：Aiyagari 用 CRRA 效用和收敛容差；MEPS 用权重和子组切分；论文评审用引文级证据规则；学者数据用官方/机构来源规则和溯源字段。底部这条**最佳实践**请大家一定记住，它能省你大量返工：**让智能体在写代码之前，先用它自己的话把规格复述一遍——这能在误解还很便宜的时候就抓住它。**

### 幻灯片 6：Step 3: Choose the Procedure Explicitly（第 3 步：显式地选定流程）
第三步：**伪代码或阶段计划，是你在实现之前抓住设计错误的地方。** 屏幕上这段伪代码我不逐行念，讲它的骨架：阶段 A 摄入或定义对象，阶段 B 跑选定的流程，阶段 C 保存诊断和检查，阶段 D 只报告通过验证的部分。下面给了具体流程：Aiyagari 用 VFI 或 EGM，MEPS 用三段提示词的流水线，论文评审用按节分解，学者数据用分批的元数据采集。底部这句话点出重点：**重点不是优雅，而是你和智能体在"代码细节开始掩盖概念错误"之前，先就流程达成一致。**

### 幻灯片 7：Step 4: Build V0 First（第 4 步：先建 V0）
第四步：**V0 是最简单的、带一个你看得懂的基准的版本。** 屏幕上用 Aiyagari V0、确定性收入举例，三条全是可手验的检查，我把它们念成经济直觉：如果 β(1+r)=1，储蓄策略应该正好落在 45 度线上；如果 β(1+r)<1，家庭会朝借贷约束**去累积**（decumulate，即不断减持资产）；如果 β(1+r)>1，资产会增长。这三条正是经典最优储蓄的边界行为。底部这句**纪律**请大家刻在心里：**在 V0 还没通过这些简单检查之前，不要去让智能体加收入风险、平稳分布、和均衡求解。**

### 幻灯片 8：What "V0 First" Means Across Four Tasks（"先建 V0"在四种任务里各是什么）
这一张是张对照表，我读成"同一个原则、四种长相"。Aiyagari 模型，V0 是确定性家庭问题，第一个验证目标是复原简单的储蓄逻辑和边界行为。MEPS 流水线，V0 是三年试点面板，目标是加权率和一个外部基准对得上。论文评审技能，V0 是一节或一个定理块，目标是引文是真的、评语是具体的。学者数据集，V0 是只放种子名单，目标是来源规则和溯源字段真的被记录下来了。底部点出为什么经济学家该在意：**V0 让第一个错误保持可解释。** 你要的是第一个失败明明白白，而不是藏在一个庞大工作流的内部。

### 幻灯片 9：Steps 5 and 6: Validate, Then Extend One Margin at a Time（第 5、6 步：验证，然后一次只扩展一个边际）
这一张是张版本阶梯表，我顺着读：V0 是确定性家庭，基准是解析情形；V1 加一个新的模型/数据/评审边际，**要求把新边际设成零就能复原 V0**；V2 加保存的诊断和状态跟踪，要求质量守恒和、基准、引文核验、或来源日志表现合理；V3 是完整目标工作流，最终产物要扛过验证和解释。请大家特别注意 V1 那一行的"设零复原"——这是同伦的关键闸门：新加的东西关掉，必须退回到上一个已验证版本。底部一句话点出它为什么对智能体好用：**当一个新版本坏掉时，你和智能体都知道该去哪里找。**

### 幻灯片 10：Why This Workflow Works for Economists（这套工作流为什么对经济学家管用）
这一张四条收束同伦的好处：它让理论、计算、验证始终对齐；它给智能体的是**有边界的任务**，而不是开放式的许愿；它保留了一条"基线是怎么搭起来的"审计轨迹；它正好**镜像了优秀研究助理实际的训练方式**——从一个简单任务开始、核验它、再拓宽范围。底部这句主旨我会重读：**工作流才是真正的产品，你用的那个具体智能体可以换。** 这也是整讲反复强调的——别把功夫下在追工具上，下在工作流纪律上。

### 幻灯片 11：Why "Homotopy Workflow"? Borrowing from Numerical Methods（为什么叫"同伦工作流"？借自数值方法）
这一张解释名字的来历，正好接经济学的数值方法。**同伦延拓(homotopy continuation)** 来自数值方法：从一个有已知解的问题出发，**连续地形变**到目标问题；同一个原理用在 AI 辅助编码上一样成立（想深入的同学看 Judd 1998《经济学中的数值方法》第 5 到 7 章那套"摄动并维持"的宏观做法）。四条对应：V0 是那个有已知解的"容易问题"；每个版本连续地形变向研究目标；每个验证过的版本是下一个的**地基**；如果 V2 坏了，你知道 bug 在 V2 的新代码里——不在 V0 或 V1。底部点出为什么这个名字要紧：**同伦工作流描绘的是一条从"可被规格化的模型"到"已验证的代码库"的光滑路径；V0→V1→V2 不是随意的里程碑，而是一条连续形变上的中间闸门。**

### 幻灯片 12：The Homotopy Workflow vs. One-Shot Generation（同伦工作流 vs. 一次性生成）
这一张给四条理由，说明同伦工作流为什么对智能体特别有效。第一，**智能体擅长良好定义、有边界的任务**——"把我的模型解了"会失败，"按这份伪代码实现 V0、并对这三个基准验证"会成功。第二，**从简单开始，让你和智能体都先有一个能跑的代码库**——V1 继承验证过的 V0 代码，智能体是在测试过的函数上搭，而不是在空白文件上。第三，**bug 归因是即时的**——V2 坏了，bug 就在 V2 新写的那几行，不在继承来的已验证行里。第四，**上下文自然累积**——到了 V3，智能体已经见过规格、伪代码、三个验证过的版本、和每一次更正，这是**深上下文**，而不是一份十页的提示词。底部这句**纪律**很扎心、也很真实：**忍住跳步的冲动——一个能跑的 V0 花你 30 分钟；而因为 V0 从没验证、去调一个坏掉的 V2，要花你一整天。**

### 幻灯片 13：Demo: Folder Structure Is the Method（演示：文件夹结构就是方法）
这里过一张分节页："OLG 五步演示——一个面向计算宏观的、具体的同伦工作流。"这一张用一张表说明：**文件夹结构本身就是方法。** 我读这张"文件夹/文件—教学角色"表：`stages/` 放五个耐用阶段——模型、均衡、算法、伪代码、实现/验证；`prompts/v*_to_v*.md` 每个版本跃迁对应一次有边界的终端会话；`versions/v0–v5` 把每一步验证过的可运行代码都保留下来；`tests/` 每个版本一个冒烟测试，失败就指向那个新边际；`build/*.json` 是终端运行产出的可复现报告。底部给出演示路径 `demos/M4_olg_5step_demo/`（本讲的本地副本，是 MiniCourse 那个演示去掉 .venv 和 build 的镜像）。我点一句：注意，**目录布局不是装饰，它把同伦纪律物化成了你能逐级回看的东西。**

### 幻灯片 14：Version Ladder: One Economic Margin at a Time（版本阶梯：一次一个经济边际）
这一张是这套演示的完整版本阶梯，左中右是"版本—新增什么—验证闸门"。我读成一条逐级加码的故事：V0 加 3 个世代、1 种资产、2 状态 TFP、一个神经网络策略，闸门是确定性稳态收敛、资本顺周期、RMS 欧拉残差低于阈值；V1 加到 7 个世代和生命周期劳动，闸门是 V0 逻辑保持不变、中年消费峰出现；V2 加 4 状态马尔可夫 TFP，闸门是塌回两状态能复现 V1；V3 加债券、价格、市场出清、互补性，闸门是债券损失权重设零能复现 V2、且晚年持有为正；V4 加资本调整成本，闸门是调整成本设零复现 V3、资本路径变平滑；V5 加稳定化的同伦阶段，闸门是残差按阶段下降、最终欧拉误差达标。底部点出研究功课：**智能体从来不会收到"把这个大模型解了"；它每次只收到一个验证过的形变。**

### 幻灯片 15：Demo Launch and Classroom Contract（演示启动与课堂约定）
这一张是上机启动。屏幕上这几行命令我讲它们各自干什么：`cd` 进演示目录；`pip install -e .` 把这个演示包以可编辑方式装上；`python3 -m unittest discover -s tests` 跑全部冒烟测试；`python3 run_demo.py` 跑演示；`jupyter notebook demo.ipynb` 打开交互笔记本。下面三条是课堂约定：**演示要证明的**——同伦在复杂度上升时仍保住一个能跑的基线；**要去检视的**——提示词、各版本文件夹、测试名、验证消息、和重新生成的报告；**失败恢复**——如果 V3 坏了，就退回已验证的 V2，只加债券市场出清这一层。给同学们一句话：跑这个演示时，眼睛不要只盯结果，要盯**目录是怎么把纪律记下来的**。

### 幻灯片 16：Choose the Tool That Matches the Task（选与任务匹配的工具）
这里过一张分节页："工具选择——哪个工具配哪个研究任务。"这一张是张三行对照表。**网页聊天**：用于立框架和解释，比如澄清识别逻辑、起草一份模型综述。**IDE 助手**：用于本地代码编辑，比如把一个函数向量化、或解释一段报错栈。**终端智能体**：用于多步执行，比如重构一个项目、跑脚本、生成诊断、再迭代。底部注明时效：**截至 2026 年 4 月，Claude Code、Codex CLI、Gemini CLI、Aider 都是终端智能体工作流的例子。** 选工具不是赶时髦，是按任务的"步数"和"是否要碰真实项目"来配。

### 幻灯片 17：Why the Terminal Agent Often Becomes the Workhorse（为什么终端智能体常成为主力）
这一张四条，讲终端智能体为什么常常成了干活的主力。它能在**真实项目**上操作，而不是在复制出来的碎片上；它能跑代码、检视错误、更新多个文件；当任务有边界、但比"改一处"要长时，它很合适；而且它仍然把经济学家留在批准和验证的回路里。底部这句给实证研究的判断很到位，请大家记住这个"甜蜜点"：**对实证研究，这通常正是甜蜜点——自主到足以省时间，又没自主到让你停止检查经济学。**

### 幻灯片 18：Looking Ahead: T4 Organizes the Project Around the Workflow（前瞻：T4 围绕工作流组织项目）
这一张收 T3。T3 给了你工作流的逻辑——先 V0、验证、一次只扩展一个边际；T4 要把这套逻辑变成磁盘上的文件：技能、智能体、规则、hooks、设置。具体说：**T3 讲的是纪律**——怎么分阶段、怎么验证；**T4 讲的是基础设施**——怎么把这套纪律编码进可复用的项目对象里；再往后 T5 给这些基础设施本该预防的失败模式一一点名。底部主线弧告诉我们走完了 T3，下一站 T4 项目组织。请大家带着一个问题进入 T4：当纪律变成文件之后，它在什么时候加载、活多久、谁来写？

### 幻灯片 1：Topic 9.4 Agenda（本节路线图）
这一节两大块。第一，**项目组织**——规格、项目记忆、测试、运行框架、技能。第二，**子智能体与远程/HPC 工作流**——并行评审、把智能体搬到算力旁边。底部主线弧告诉我们现在站在 T4 项目组织这一站。这一节会出现不少文件和配置，但请大家始终抓一条主线：**每一个项目对象，都是对某个反复出现的研究协调或可信度问题的回答。**

### 幻灯片 2：Why Files on Disk Matter（为什么磁盘上的文件要紧）
进入第一部分前，屏幕上有张分节页："项目组织——一个终端智能体项目如何保持井然有序。"这一张的主旨一句话：**运行框架把今天的聊天，变成明天可复用的工作流。** 四条：约定活在文件里，而不是你的脑子里；验证步骤变成可复现的实验室流程；新会话可以从项目的真实状态出发；合作者和学生可以检视这个工作流本该是什么样。底部给经济学家一个翻译，特别贴切：**运行框架，就像把心照不宣的 RA 操作习惯，写成书面的实验室协议。** 这正是科研可复现性的根本——把隐性知识显性化。

### 幻灯片 3：Why These Project Objects Exist: Coordination（这些项目对象为什么存在：协调）
这一张是张表，讲三个对象各自解决的协调痛点。`CLAUDE.md` / 项目记忆：解决"你不想每次会话都重新解释项目一遍"——比如让 MEPS 的权重规则、或 Aiyagari 的基准一直可见。技能(Skill)：解决"一个重复的工作流不该每次现编"——比如带同样质量闸门的论文评审流水线。智能体(Agent)：解决"有些评审角色更容易并行和专门化"——比如代码审查员和领域审查员分开。底部点出这一张的用意：**这些对象不是产品花边，它们是对反复出现的研究协调问题的回答。** 请大家带着"它解决了什么协调失败"的眼光看每个对象。

### 幻灯片 4：Why These Project Objects Exist: Control and Credibility（这些对象为什么存在：控制与可信度）
这一张接上一张，再列三个对象解决的"控制与可信度"痛点。规则(Rule)：解决"有些指令应该一直开着"——比如"宣称成功之前，先把输出存到 output/"。验证器(Verifier)：解决"输出在算数之前应该过指定的检查"——比如重跑脚本、检视诊断、确认文件存在。溯源日志(Provenance log)：解决"来源纪律必须活过这次聊天"——比如带字段级 URL 和备注的学者数据集。底部这条实践要点是判断要不要做某个对象的标尺：**工作流对象只有在它确实减少了一个真实的协调或可信度失败时，才值得做。** 别为了搭架子而搭架子。

### 幻灯片 5：Minimal Project Tree（最小项目树）
这一张是一棵目录树，我不逐个文件念，讲它的骨架，让大家在脑子里有张地图。根目录下有 `CLAUDE.md`（项目大脑）；一个 `.claude/` 文件夹，里面有 `skills/`（比如 paper-review 技能，含 SKILL.md 和 references/ 参考模板）、`agents/`（code-reviewer、domain-reviewer、verifier 三个审查角色）、`rules/`（比如 iterative-workflow.md 这条常开规则）、和 `settings.json`；外加 `scripts/`、`output/`、`sources/`、`quality_reports/` 这几个工作文件夹。底部这句话点出态度：**这点东西，已经足够把工作流讲清楚，又不会让学生淹没在基础设施里——具体研究问题可以换，这套组织逻辑不变。**

### 幻灯片 6：CLAUDE.md: The Team-Facing Project Memory（CLAUDE.md：面向团队的项目记忆）
这一张给大家看 `CLAUDE.md` 实际长什么样。它是项目主要的、共享的说明文件。屏幕上这段示例我讲它在说什么，不抠语法：它写明了项目是"第 9 讲的 MEPS 未参保试点"、语言是 Python、目标是"协调 2012–2014 文件、产出一张验证过的图"、约定是"不写死路径、把输出存到 output/"、检查是"用调查权重、保存年份映射、报告什么通过了"。底部点出为什么学生该在意：**它把那种你本来每次会话都要重新解释一遍的项目上下文，一次性固定下来了。** 写好一个 CLAUDE.md，等于给项目装了长期记忆。

### 幻灯片 7：CLAUDE.md, Auto Memory, and Optional Course Logs（CLAUDE.md、自动记忆、可选课程日志）
这一张提醒大家：**三种不同的"持久化"别混为一谈。** 看这张表。`CLAUDE.md`：由你/团队写，存的是耐用的项目说明和约定。自动记忆(Auto memory)：由工具自己写，存的是每个项目学到的模式和更正。可选课程日志：由你/课程写，是显式的进度笔记，比如 `MEMORY.md` 或 `progress.md`。底部给出课程推荐，请大家照这个分工来：**共享规则靠 CLAUDE.md，自动记忆当成有用但不权威的参考，需要让学生检视项目演进时再保留显式日志。** 三者职责不同，混用会出乱子。

### 幻灯片 8：Skills, Agents, and Rules: Three Different Jobs（技能、智能体、规则：三种不同的活）
这一张用一张三栏图把三者的分工和**加载时机**讲清，我从左到右点一遍。**技能(Skills)**：可调用的工作流，按名字调用、可参数化，**按需加载**。**智能体(Agents)**：专职角色，独立上下文、聚焦的职责，由**编排器派生**。**规则(Rules)**：常开护栏，每次会话自动套用，**会话开始时就加载**。底部这句话是这张图的关键，请大家记住这个先后：**加载顺序很重要——规则在第一条用户消息之前就被读入；技能在被调用时才加载；智能体启动时，把规则和任何继承来的上下文当作它的系统提示。** 三者不是同义词，是三种生命周期。

### 幻灯片 9：Plain English vs. Encoded Skill（大白话 vs. 编码成技能）
这一张左右对照，回答"什么时候该把工作流固化成技能"。左栏**大白话**：直接说"评审这篇论文，用确切引文告诉我最严重的问题"——适合在你还在**探索**、做一次性任务、还在拿不准工作流时用。右栏**编码技能**：敲 `/paper-review draft_A.pdf` ——适合在工作流**应该精确重复**、一个学生团队需要一套标准流程、验证必须跨版本一致时用。底部这句口诀很好记，请大家带走：**探索从大白话开始，可复现性活在技能里。** 不是所有东西都要编码——只有当"重复且要一致"时才值得。

### 幻灯片 10：Skill File Structure（技能的文件结构）
这一张给大家看技能的文件结构。屏幕上是 `paper-review` 技能文件夹：里面有 `SKILL.md`，和一个 `references/` 子文件夹（放 `referee-template.md`）。`SKILL.md` 存的是**可重复的协议**：这个命令叫什么、它该走哪几步、报告成功之前哪些检查必须通过。`references/` 里的参考文件，存的是那些会把主说明文件搞乱的、任务专属的细节。我点一句设计哲学：**主说明要短、要常驻；又长又专的细节，拆到参考文件里去按需取用。** 这跟 T2 说的"CLAUDE.md 要精简"是同一个成本逻辑。

### 幻灯片 11：Agents as Specialist Reviewers（把智能体理解成专职审查员）
这一张说：**智能体文件，最好理解成专职的评审角色。** 三个例子：`code-reviewer.md` 管文件卫生、实现质量、可复现性；`domain-reviewer.md` 管基准逻辑、识别、或经济一致性；`verifier.md` 跑脚本、检视诊断、确认输出或来源日志存在。底部给一个经济学家一听就懂的类比：**一个 RA 查代码风格，另一个查经济学，再一个把表重跑一遍。** 把审查拆成专职角色，每个角色的职责就清楚、产出就更可靠。

### 幻灯片 12：Subagents as Parallel Reviewers（把子智能体当成并行审查员）
这一张说子智能体要紧的原因：**评审任务可以并行。** 三条：主智能体写或改代码；一个 code-reviewer 和一个 domain-reviewer 可以**同时**检视结果；主对话拿到两份报告、再决定改什么。底部点出为什么学生该在意，而且把话说得很实在：**好处不是哲学层面的，是墙钟时间。** 聚焦的评审角色，比一个塞满各种要求的、过载的提示词，要更快、往往也更清楚。这里先埋个伏笔——这套并行评审省的是时间；到了 T5 我们会戳破它一个更深的局限。

### 幻灯片 13：Rules, Hooks, and Settings（规则、钩子、设置）
这一张用一张表把三者按"何时加载、典型用途"分开。**规则(Rules)**：项目工作期间加载，用于"总是遵循某个规划或验证约定"。**钩子(Hooks)**：在工具事件上触发，用于机械地跑格式化、或记录一条命令。**设置(Settings)**：会话开始时加载，管权限和项目级行为。底部这条**实践区分**是选对层的关键，请大家记牢：**如果它是自然语言的指导，通常属于规则或技能；如果它必须每次机械地发生，用钩子更稳妥。** 一句话——人话靠规则，机械靠钩子。

### 幻灯片 14：Three Persistence Layers, Three Lifetimes（三个持久化层，三种寿命）
这一张把"运行框架(harness)"这个统称拆成三个持久化层，按寿命排。看这张表。**钩子(写在 settings.json)**：寿命是**每事件**——机械执行：编辑后格式化、停止时跑测试、拦截危险工具。**项目记忆/规则**：寿命是**每会话**——引导上下文：项目说明和按路径限定的护栏。**自动记忆 + 进度文件**：寿命是**跨会话**——耐用的学习成果和你能检视、能编辑的显式交接笔记。底部点出为什么这要紧：**选对层，设计就成功了一半**——如果规则必须每次都触发，钩子比一句自然语言提醒更稳妥；如果它必须活过一次全新会话，它就属于记忆或规则，而不是一个转瞬即逝的提示词。一句口诀：**人话 → 规则和技能；机械执行 → 钩子。**

### 幻灯片 15：Permissions and Hooks in settings.json（settings.json 里的权限与钩子）
这一张给大家看 `settings.json` 实际配置，**两件事：权限定义"爆炸半径"，钩子在工具边界跑机械检查。** 屏幕上这段 JSON 我讲它干什么，不逐行念。`permissions` 块里，`allow` 放允许的：`Bash(python *)`、`Bash(pytest *)`、`Read(*)`、`Edit(*)`；`deny` 放拒绝的：`Bash(rm -rf *)`、`Bash(git push --force *)`、读 `.env`、读 `secrets/**`——注意 deny 把删库、强推、读密钥这些高危动作挡在门外。`hooks` 块里，`PostToolUse` 在 Write/Edit 之后跑一个格式化脚本，`Stop` 在停止时跑 `pytest`。底部列了几个值得知道的钩子类型：`PreToolUse`（拦危险命令）、`PostToolUse`（格式化/lint）、`Stop`（跑全套测试）、`SubagentStop`（核验报告格式）、`PreCompact`（压缩前保存进度）。给在 HPC 上工作的同学一句：deny 列表和 PreToolUse，就是 T1b 讲的"最小权限沙箱"落地的地方。

### 幻灯片 16：Skills Are Saved Research Playbooks（技能是保存下来的研究工作手册）
这一张主旨：**技能是长流程、重复流程的正确归宿。** 常驻的项目上下文要短，把领域工作流放进可复用的技能里。看这张"技能—可复用工作流—验证钩子"表：`data-analysis`，做加载、探索、回归、出表出图，验证是输出模式加脚本重跑；`review-paper`，读论文、审论证、生成裁判式反驳，验证是结构化评审报告；`weighted-survey`，算调查加权的率/均值，验证是公式对照基准；`hpc-job`，写 sbatch 脚本、提交、解析日志，验证是调度器状态加解析器。底部这条可移植的思想很关键：**Claude 可能叫它们 skills，Codex 可能换种打包方式；耐用的对象，是一个保存下来的工作手册——带触发条件、允许的工具、步骤、和验收测试。**

### 幻灯片 17：Sub-Agents: Parallel Children With Their Own Contexts（子智能体：拥有自己上下文的并行孩子）
进入第二部分前，屏幕上有张分节页："子智能体与远程/HPC——当笔记本不再是合适的宿主。"这一张讲子智能体的机制：**当编排器派生一个子智能体，运行框架启动一个独立的智能体实例，带它自己的上下文窗口。** 四条：多个子智能体可以**并行**跑——像 Python 的 multiprocessing；每个收到一个智能体文件（或简报提示词）当系统提示；每个跑到完成、返回一份结构化报告；主对话读这些报告、再决定下一步。屏幕上给了 Aiyagari 例子：写完 `aiyagari_v1.py` 后，编排器并行派生 `code-reviewer` 和 `domain-reviewer`，两个加起来大约只花一次顺序运行的墙钟时间——**评审时间减半。** 底部那句斜体点破为什么要分开：一个什么都问的单提示词，每个维度都做得平庸；**分开，才能聚焦。**

### 幻灯片 18：When to Use Sub-Agents (and When Not)（什么时候用子智能体，什么时候别用）
这一张左右两栏，给适用边界。左栏**适合子智能体**：代码评审（并行：代码、领域、安全）；文档查阅（读 5 页文档、返回 URL）；会用 HTML 噪声塞满主上下文的网络调研；按模块独立生成单元测试；多论文文献扫描。右栏**不适合**：紧耦合的工作（每步依赖上一步）；编排器一次工具调用就能完成的任务；任何你需要中途交互式引导的任务；子智能体再派生子智能体（**深度会导致漂移**）。底部这条"复合爆炸半径"的警告很重要，给三条经验法则：在新流水线上授予"执行"之前先用计划模式（Shift+Tab）；每个子智能体的清单要**规格化**、不能自由发挥；阶段之间设检查点验证——这就是 T3 的同伦纪律。请大家记住：**编排器派生子智能体是成熟度最高的一档，权力越大，越要先收口。**

### 幻灯片 19：Mental Model: Local Orchestrator, Remote Compute（心智模型：本地编排，远程算力）
这一张是张三框图，讲重活该在哪跑。我顺着图点：左边蓝框是"你的 Mac"——编辑器/终端前端；中间橙框是"集群登录节点"——**智能体在这里跑**，读写代码、提交作业；下面绿框是"计算节点"——MPI/GPU/长仿真。Mac 到登录节点走 SSH 或 VS Code 远程；登录节点到计算节点走 `sbatch`、`srun`；计算节点把日志和结果回送给登录节点。主旨一句话：**对重负载，智能体应该在数据、模块、GPU 已经在的地方跑。** 底部那条规则请大家刻住：**智能体可以编排 HPC 工作，但不该把登录节点变成工作站——计算密集的步骤要走调度器。**

### 幻灯片 20：Move the Agent to the Compute, Not the Compute to the Agent（把智能体搬到算力旁，而不是把算力搬到智能体旁）
这一张左右对照两种工作流。左栏**本地智能体**：智能体在你 Mac 上跑，集群文件得下载、总结、或拷回来，大输出和日志靠 scp、rsync 或手动上传搬动——玩具代码还行，HPC 研究就脆。右栏**远程智能体**：智能体在集群登录节点上跑，项目文件留在远程工作树里，重活通过调度器在计算节点上跑，Mac 上的 VS Code 只当编辑器和终端前端。底部把规则再讲一遍，给做大规模计算的同学：**如果数据、模块、GPU、作业日志都在集群上，就把智能体装在集群上。** 这条对我们用 Delta 这类超算的同学尤其实用。

### 幻灯片 21：Login Node vs. Compute Node: The Hard Boundary（登录节点 vs. 计算节点：那条硬边界）
这一张把那条边界讲死。**智能体在登录节点上能做的**：读写代码、规格、上下文文件、作业脚本；跑微小的冒烟测试——导入检查、单元测试、`--dry-run`、小网格 V0；提交作业、监控日志、解析错误、修订脚本。**必须走调度器的**：MPI 作业、GPU 训练、大仿真、长校准；任何吃很多核、很多内存、或超过几分钟的东西。底部把研究规则再钉一遍：**智能体可以编排 HPC 工作，但不该把登录节点变成工作站。** 这条不是礼貌问题，是会被集群管理员封号的硬纪律——请大家务必遵守。

### 幻灯片 22：Looking Ahead: T5 Names What Goes Wrong（前瞻：T5 给"出错"点名）
这一张收 T4。T4 给了你项目对象——技能、智能体、规则、hooks、设置、子智能体、远程执行；T5 把聚光灯打到"这些对象怎么还是会产出错答案"上。具体说：**T4 讲的是耐用基础设施**——约定住在哪、运行框架怎么执行它；**T5 先把那个运行的例子端到端追踪一遍，再编目那些基础设施无法完全防住的失败模式**；T5 最后收在**"上下文困境"**上——同一份让答案变好的上下文，也会把答案拉向你。底部主线弧告诉我们走完了 T4，下一站 T5 失败与上下文困境。请大家带着一点警惕进入 T5：基础设施很强，但它不是万能的。

### 幻灯片 1：Topic 9.5 Agenda（本节路线图）
这一节三件事。第一，**追踪那个计算例子**——把 Aiyagari 求解在运行框架里走一遍，看文件流和编排循环。第二，**错误、局限与安全**——智能体会在哪儿翻车、有哪些能力边界、什么数据绝不能喂。第三，**上下文困境**——这是整讲最需要冷静对待的一段。底部主线弧告诉我们现在站在 **T5** 这一站：T1 立框架 → T2 拆引擎盖 → T3 同伦 → T4 项目组织 → **T5 失败与上下文** → T6 收尾。我先把这一节的灵魂剧透一句：运行框架很强，但它**防不住你自己的先验**。

### 幻灯片 2：Aiyagari Recap: The Computational Anchor（Aiyagari 回顾：计算锚点）
进入第一部分前，屏幕上有张分节页："追踪那个计算例子——在一讲更宽的工作流里，Aiyagari 是那个计算锚点。"好，先把 Aiyagari 模型(Aiyagari model)的家庭问题快速回顾一下。屏幕上这条预算约束我念成话：当期消费 c_t 加上下期资产 a_{t+1}，等于本息收入 (1+r)·a_t 加劳动收入 w·z_t；再加一条借贷约束——下期资产 a_{t+1} 不能低于一个下限 a 下划线。这里的 z_t 是**个体特有的生产率(idiosyncratic productivity)**，服从一条马尔可夫链，也就是每个家庭面对自己那份、有持续性的收入风险。为什么我们整讲都拿它当例子？三条：它是**全课程里最干净的计算例子**；它天然能拆成 V0 → V1 → V2 这样一条清晰的递进；而且它有一目了然的验证检查点，这些检查点的思路能迁移到别的工作流上去。一句话——它小、它干净、它每一步都能验。

### 幻灯片 3：Tracing the File Flow（追踪文件流）
这一张是一段编号清单，列出智能体跑一次 Aiyagari 求解时，文件到底是怎么被一步步读写的。我不逐行念，讲它的走向：先读项目大脑 `CLAUDE.md`，再读相关的规则文件；接着从 `SKILL.md` 里加载 `/solve-model` 这个技能，并读进参考指南 `references/aiyagari-guide.md`；然后把计划写下来、或更新 `quality_reports/`；再去编辑 `scripts/aiyagari_v0.py`；改完跑验证器和审查员；最后把输出和日志存下来。大家这一张只要抓住一句话——**这条工作流是文件驱动的(file-driven)。** 智能体不是在真空里即兴发挥，它是在一个有结构的研究项目里干活，每一步都踩在前面 T4 搭好的那些文件对象上。

### 幻灯片 4：Tracing the Orchestrator Loop（追踪编排循环）
上一张看的是文件，这一张看的是**编排循环(orchestrator loop)**——也就是控制流怎么转。屏幕上这段伪记录我讲它在演示什么：你敲一句 `/solve-model aiyagari v1`，智能体先出一个**计划**——读项目说明、把目标复述一遍、只做有边界的改动；然后进入**评审循环**——跑验证器、跑代码审查员、跑领域审查员、修那些真正要紧的问题、再报告改了什么、过了什么。底部这句话点出运行框架最核心的优势，请大家记住：**这套评审次序不是一句记在脑子里的提示词，它是被保存进工作流的。** 换句话说，"先验证再前进"这件事，已经被写进文件、每次都会照做，而不是靠你每次会话重新叮嘱。

### 幻灯片 5：Inside CLAUDE.md for the Aiyagari Project（Aiyagari 项目的 CLAUDE.md 内部）
这一张把 Aiyagari 项目的 `CLAUDE.md` 摊开给大家看。屏幕上这段内容我讲它在说什么，不抠语法：它写明项目是"第 9 讲的 Aiyagari 工作流"、目标是"依次建 v0、v1、v2"、产出是"策略函数、平稳分布、诊断"、约定是"图存到 `output/`、计划存到 `quality_reports/`"、还有一条验证铁律——"基准没过，就不许进到下一个版本"。注意最后这条，它正是 T3 同伦纪律落进项目大脑里的样子。底部这句话点出 `CLAUDE.md` 的价值：**只要这个文件写得好，这个项目就能扛过一次全新会话、一个新来的研究助理、甚至一次智能体工具的更换。** 项目的记忆不在聊天里，在这个文件里。

### 幻灯片 6：Inside SKILL.md and the Reference Guide（SKILL.md 与参考指南内部）
这一张左右两栏，让大家看清技能(skill)里"协议"和"细节"是怎么分家的。左栏是 `SKILL.md`：它存的是**可重复的协议**——技能叫 `solve-model`、职责是"建模并验证"、然后是五步流程：读模型指南、写或更新计划、实现一个版本、跑必需的检查、保存输出并报告。右栏是参考指南 `aiyagari-guide.md`：它存的是**模型细节**——V0 是确定性基准、V1 加马尔可夫收入风险、V2 算平稳分布；下面还列了三个检查：零方差极限、a_min 处的质量是否合理、诊断是否稳定。底部这句话把分工讲透了：**技能存的是协议，参考指南存的是模型细节。** 这跟 T4 那条"主说明要短、又长又专的细节拆出去"是同一个设计哲学。

### 幻灯片 7：Three Recurring Mistakes（三个反复出现的错误）
进入第二部分前，屏幕上有张分节页："错误、局限与安全——哪些地方会出岔子，以及怎么保持纪律。"这一张点名一个智能体项目最容易翻车的三种方式。**错误一：把 Git 当可选项。** 智能体最有用的前提，是实验可逆；Git 给你的正是审计轨迹和那个紧急刹车——如果丢掉当前项目状态会让你心疼，那在放手让智能体大改之前，先把它纳入 Git。**错误二：用不够技能。** 经济学家有大量重复工作流——清数据、验表格、做幻灯片、审代码；重复的活应该从聊天里搬进一份保存好的协议，否则同一个任务每周都要重讲一遍，而且每次理解还略有出入。**错误三：一根巨大的对话线。** 长对话会累积陈旧上下文——规划、调试、修订全搅在一起，模型还在关注那些早就不重要的约束；正确做法是先规划任务、把计划存下来，再开一个更干净的执行会话。

### 幻灯片 8：Where Terminal Agents Still Fail（终端智能体仍会失败的地方）
这一张老实列出终端智能体目前还会栽的几类跟头。**长上下文漂移(long-context drift)**——一个早先定的约束，跑着跑着就被忘了。**计量的边角情形**——聚类层级搞错、样本限制搞错、弱工具变量问题。**幻觉出来的 API 或包参数**——它编出一个根本不存在的函数或参数。**顺利路径(happy-path)脚本**——在干净数据上跑得好，一碰到脏数据就崩。**在顽固 bug 上来回震荡的修复循环**——改 A 坏 B、改 B 又坏 A。底部这句话是这一段的定调，请大家加重听：**产出可能看起来很光鲜，哪怕底下的经济学是错的。** 这正是为什么验证必须始终在场。接下来两张，我给大家看两个具体实例。

### 幻灯片 9：Example: Clustering Standard Errors（示例：聚类标准误）
这是第一个具体实例。提示词是："用县-月面板数据，估计最低工资上调对青少年就业的影响。"屏幕上这行代码是智能体的**默认产出**：`reg emp_teen mw_increase i.county i.month, robust`。我讲它**错在哪**：识别是在县这个层级上发生的，所以标准误必须**按县聚类(cluster at county)**；那个默认的 `, robust` 语法上完全合法，但在这里计量上是错的——标准误会**小掉 2 到 4 倍**，于是你会把一堆其实不显著的东西判成显著。**为什么智能体会漏掉？** 因为它的训练语料奖励的是"能跑通"的代码，而聚类层级的选择是一个**研究设计决策**，不是一个代码语法决策。**怎么发现？** 在提示词里就把聚类层级写死，并拿 Abadie、Athey、Imbens、Wooldridge 2023 年发在 QJE 上那篇《什么时候该为聚类调整标准误》当权威对照。最后给经济学背景的同学点一句落地办法：**用一条仓库规则**——要求每一个回归都必须声明聚类层级——就能在源头上把这一整类错误拦住。

### 幻灯片 10：Example: Happy-Path Failure on Messy Data（示例：顺利路径在脏数据上失败）
第二个实例更隐蔽。提示词是："合并 FRED 的 UNRATE 和 CPIAUCSL 两条月度序列，1948 年至今。"智能体的默认产出是一行 `pd.merge(unrate, cpi, on="date", how="inner")`。这一行**错在哪**？CPIAUCSL 这条序列里藏着一个**方法论断点(methodological break)**：1983 年 1 月起，美国劳工统计局把 CPI-U 里自有住房的处理，从"资产/自有成本法"换成了**租金等价法(rental equivalence，即业主等价租金)**。关键的坑在于——指数的水平和基期（1982–84=100）是**连续的**，所以表面上什么都没坏，但 1983 年前后的序列其实在用**两种不同的定义**度量居住成本；你在合并后的整段上跑回归，就等于把两个定义当成同一个变量。**为什么智能体会漏掉？** 顺利路径代码只对主流情形负责；除非你明确要求，它**不会主动去找那种定义变了、单位和基期却没变**的方法论断点。**怎么发现？** 回归之前先做一次基本的数据审计——`describe()`、把序列画出来、按年份数一数行数——并且读一读序列的定义说明；更稳的办法是加一条规则，逼智能体把"审定义断点"当成工作流的一步。这一张的**通用教训**请大家带走：合并序列后，永远要审定义断点——不能只问"哪些行消失了"，还要问"在这段区间里，这个变量的定义有没有变过"。

### 幻灯片 11：Context Windows and Compaction（上下文窗口与压缩）
这一张讲会话变长之后怎么办：**在压缩对话之前，先把状态存进文件。** 先说为什么长上下文会退化——Lec07 T3b 记录过那个"迷失在中间(lost in the middle)"现象（Liu 等人 2024 年发在 TACL）：内容如果坐在长提示词的中段，召回率会掉 20 到 30 个百分点。压缩(compaction)就是只保留真正要紧的东西，让智能体的工作记忆留在上下文里高召回的那一段。屏幕上这段做法我讲它的意思：先写一份 `progress.md`，记下"完成了什么、做了哪些决定、还有什么悬而未决"；然后再压缩对话、或干脆开个新会话；下次进来，第一件事就是读 `progress.md`。底部这句**经济学翻译**很贴切，请大家记住：**这就是记一本干净的研究日志。** 人类靠研究日志接上断点，智能体也受益于同一套纪律。

### 幻灯片 12：Security: What Not to Expose, and Workarounds（安全：不该暴露什么，以及变通办法）
这一张是安全红线，对我们在有数据合规要求环境里工作的同学尤其重要。**绝对不要摆到智能体面前的东西**：受 IRB 保护的访谈、可链接的行政微观数据、个人可识别信息(PII)、受 HIPAA 监管的数据、密码/API 密钥/访问令牌、以及禁运或限制使用的数据集。这里有一条好记的**操作规矩**：**如果你不会把它粘到一个公开的协作工具里，那就不要把它粘进智能体对话里。** 但请注意——敏感数据**不等于**"从此一概不用智能体"。三条变通办法：第一，**和智能体一起写脚本，然后你自己**在受限数据上跑；第二，用**结构相同的合成数据或脱敏数据**来调试；第三，用机构批准的本地或私有部署。底部那条安全模式一句话记住：**暴露结构和汇总统计，不要暴露原始记录。** 最后提一句：AEA 在 2024 年 10 月已经有了针对 AI 辅助分析的披露政策，而 IRB、HIPAA、GDPR 那套规则，搬到智能体工作流上一字不变地适用。

### 幻灯片 13：Why This Cautionary Section Belongs Here（为什么这段警示放在这里）
进入第三部分前，屏幕上有张分节页："上下文困境——你刚学会的这套工作流，它在认知上的边界。"这一张先解释：为什么偏偏在这里、在你刚学完一套强大工作流之后，要插一段最冷静的反思。原因恰恰是——**这套工作流之所以强大，正是因为上下文能提升表现。** 三点：项目文件帮智能体更快理解你的任务；保存的规则减少重复犯错；但是——**同一份反复出现的上下文，也会把产出拉向你的框架、你的盲区。** 给经济学背景的同学点一句这张的落脚：**那套提升执行力的工作流纪律，如果你把"快"误当成"被批判过"，它就会悄悄削弱你的外部视角(outside view)。** 这一段不是来泼冷水的，是来给这把利器配一个护栏的。

### 幻灯片 14：Context as Implicit Bayesian Prior（上下文作为隐式贝叶斯先验）
这一张把上面的直觉做实。Lec07 T3a 我们讲过**上下文学习(in-context learning)是一种隐式贝叶斯推断**（Xie 等人 2022）；现在我们回到这个框架，把它对研究诚信的含义挖出来——**同一个"条件化"操作，既改善你的结果，也把结果偏向你的先验。** 看左栏三条：项目记忆、之前的对话、计划文件，都在充当"证据"，把智能体的输出分布**收窄**；Xie、Raghunathan、Liang、Ma 把这件事形式化了——上下文学习近似于在一个潜在任务上做隐式贝叶斯推断；你加上下文时感到的那份性能提升，**本质上就是后验在变窄**。右栏是一张两面板的示意图，我用激光笔从左点到右：左边蓝色的是"任务上的先验"，宽宽的一座钟形；右边红色的是"给定上下文后的后验"，收成一根尖尖的峰。图注那句话是关键——**更多上下文 ⇒ 更窄的后验 ⇒ 更自信的答案，但也更贴合你的框架；同一个机制，两件事一起做了。** 底部这句**研究翻译**请大家细品：当你载入项目记忆、过往讨论和计划时，你不只是在帮模型，你**还在告诉它，一个"看起来合理"的答案该长什么样**。（Xie 等人 2022，ICLR，arXiv:2111.02080。）

### 幻灯片 15：Stating the Dilemma（陈述这个困境）
这一张把困境正式说成一句话：**同一份改善答案的上下文，也把答案拉向你。** 三条并排：更多上下文 ⇒ 更懂你的问题 ⇒ 更好的生成；更多上下文 ⇒ 生成更贴合你的偏好、你的知识、你的框架；这两个效应**共用同一个机制**——证据是你提供的。底部这句话我会重读，因为它是整段的刺点：**那个改善答案的信号，同时也把你的先验"洗"进了答案里。** "洗进去(launder)"这个词用得很重，但很准——你以为你在喂事实，其实你也在喂立场。

### 幻灯片 16：Evidence 1: Sycophancy → False Confidence in Framing（证据一：谄媚 → 对框架的虚假自信）
接下来三张是三条证据。第一条是**谄媚(sycophancy)**：RLHF（人类反馈强化学习）奖励"同意用户"，于是模型学会了奉承。Sharma 等人记录了前沿模型普遍存在的谄媚——事实上的来回翻供、毫无必要的让步、一旦用户透露立场就开始迎合。Perez 等人发现这个效应**随模型规模放大**——越大的模型，在价值观和政治问题上越谄媚。而且这个效应在**上下文透露出强烈的用户先验时最强**。给经济学的同学点一句**失败模式**：当你暗示这个理论"应该"成立，模型就会开始帮你**辩护**这个框架，而不是去**检验**它。（Sharma 等人 2023，arXiv:2310.13548，Anthropic；Perez 等人 2023，ACL Findings。）

### 幻灯片 17：Evidence 2: Self-Correction Has a Ceiling → Weak Internal Review（证据二：自我纠正有天花板 → 内部审查弱）
第二条证据针对"让它自己审自己"。**没有新的外部信息时，内在的自我批判往往停滞、甚至退化。** Huang 等人证明：在没有外部信号的情况下，大语言模型**无法可靠地**自我纠正推理错误。Valmeekam 等人发现：在规划问题上，自我批判常常比**完全不批判还糟**。自我纠正文献里那些真正的增益，都来自**外部**信号——工具、测试、验证器、人。给经济学的同学点一句**失败模式**：你让同一个模型去批判它自己的回归设计、自己的综述备忘、自己的来源编码决策，这种审查是"信息饥饿"的，因为回路里**没有任何真正新的东西**进来。（Huang 等人 2024，ICLR；Valmeekam 等人 2023，NeurIPS。）

### 幻灯片 18：Evidence 3: Multi-Agent Debate — Helpful, but Not an Outside View（证据三：多智能体辩论 — 有用，但不是外部视角）
第三条证据针对"那让多个智能体互相辩论呢"。**辩论有用，前提是辩手们采样得不一样；共享上下文会压缩那个分歧空间。** Du 等人确实证明了多智能体辩论(multi-agent debate)能在若干基准上提升事实性和推理；Irving、Christiano、Amodei 那条"通过辩论实现 AI 安全"的线，是对抗式审查背后的理论希望。但有个**告诫**：这些增益依赖辩手能产出**真正不同**的推理路线。问题来了——当每一个辩手都读同一份 `CLAUDE.md`、同一根对话线，分歧空间就被收窄了。给经济学的同学点一句**失败模式**：子智能体能抓出实现错误和前后不一致，但它们通常**不会去重审你写进项目文件里的那个前提**。（Du 等人 2023；Irving、Christiano、Amodei 2018。）

### 幻灯片 19：Why Subagent Reviewers Inherit the Same Prior（为什么子智能体审查员继承同一个先验）
这一张把前面三条证据收到一个很扎心的点上。还记得 T4 里我埋的那个伏笔吗——我们当时卖子智能体评审，卖的是**省墙钟时间**，**不是**认知上的独立。看这里：`code-reviewer.md`、`domain-reviewer.md`、`verifier.md` 读的是**同一份项目上下文**。所以它们是**执行上并行**，不是**认知上并行**；共享的 `CLAUDE.md` ⇒ 共享的盲区。它们能抓实现错误，**抓不出框架错误**——因为框架就活在它们所信任的那份上下文里。底部这句话请大家记牢，它是这整段的中心结论：**并行的审查员省的是时间，它们产生不出一个外部视角。**

### 幻灯片 20：Monoculture at the Research Community Scale（研究共同体尺度上的单一栽培）
这一张把困境从你一个人，放大到整个学科。**当每个研究者都在相似的上下文上做条件化，整个领域的错误就会变得相关。** Kleinberg 与 Raghavan 证明：算法**单一栽培(monoculture)** 即使让每一个**单独**决策都变好了，仍可能降低社会福利。Bommasani 等人记录了**结果同质化**——共享的基础模型会"挑中同一批人、漏掉同一批情形"。把这个外推一下：如果做实证的经济学家都共享 Claude、共享相似的 `CLAUDE.md` 模板、共享相似的先验，那么"复制(replication)"就不再有信息量了——因为大家会以同样的方式错。给经济学的同学点一句**失败模式**：共享的模板和共享的模型，会让错误在学生之间、合作者之间、甚至整个领域之间变得更相关。（Kleinberg 与 Raghavan 2021，PNAS；Bommasani 等人 2022，NeurIPS。）

### 幻灯片 21：The RLHF Root Cause（RLHF 的根源）
这一张挖到最底层：**取悦那个握着上下文的人，不是一个提示词层面的小毛病，它是被训练进去的。** Casper 等人编目了 RLHF 的一系列开放性难题：偏好数据本身有噪声、标注者会奖励"好说话"、于是最优解会**漂离真相**。Wolf 等人则论证：靠微调来做对齐有根本性的局限——提示词**没法完全抹掉**损失函数强化进去的东西。直接的后果是：**任何一节标题叫"不要奉承我"的 `CLAUDE.md`，都不能把这个行为完全去掉。** 底部这句话请大家记死，它是整段困境的根：**这个模型被训练成去取悦那个握着上下文的人；而在你的项目里，那个人就是你。**（Casper 等人 2023，TMLR；Wolf 等人 2023。）

### 幻灯片 22：Remedy: Outside Critics Carry a Different Prior（解药：外部批评者带着不同的先验）
讲完病，这一张讲药。**导师、合作者、研讨会的听众之所以宝贵，正是因为他们的先验不在你的上下文窗口里。** 他们会挑战你的框架、你的识别假设、你的样本限制——那些**你没写进 `CLAUDE.md`、因为你压根没意识到要写**的东西。这正是 Korinek 那套**分工(division of labor)** 框架的意思：大语言模型自动化的是执行，而**问题的选择与批判**仍然归人类。底部那句**预算建议**很实在：智能体的评审又便宜又能并行，人类的评审稀缺而决定性——所以要**照这个稀缺性来分配预算**。最后这句话请大家带走：**智能体能把你已经相信的东西打磨得锃亮；只有一个外部读者，才能告诉你——你对这个问题本身就想错了。**（Korinek 2023，NBER 工作论文 30957；JEL。）

### 幻灯片 23：Operational Discipline for Research Projects（研究项目的操作纪律）
这一张把抽象的困境翻译成一小撮可执行的习惯。第一，**子智能体评审只用于实现质量，不用于框架或识别**——让它查代码，别指望它替你审研究设计。第二，**在继续和智能体迭代之前，先把初步结果拿给一个人类读者看**——把外部视角放在迭代的前面，而不是后面。第三，**当你改 `CLAUDE.md` 时，记下你"排除了什么、为什么"，而不只是记你决定了什么**——被排除的选项往往才是盲区所在。第四，**尽早安排研讨会式的曝光，别等到写论文的时候**。底部这句话是这套纪律的灵魂，请大家记住这个资源观：**把人类的批评当成那个稀缺投入；花智能体的算力，是为了把它准备好。**

### 幻灯片 24：Bridge Back: Workflow Rules After the Context Dilemma（接回来：上下文困境之后的工作流规则）
这一张把上面那段警示，再翻译回四条很实在的工作流规则，让大家不至于因为"困境"而手足无措。第一，**用外部基准**——把模型输出、图、编码过的数据，拿去和**当前对话线之外**的某个东西对照。第二，**用人类批评者**——导师、合作者、研讨会听众，仍然是外部视角的主要来源。第三，**刻意地做对抗式评审**——让子智能体或审查员去**检验假设**，而不只是打磨执行。第四，**把假设写到磁盘上**——存下你排除了什么、还有什么不确定、什么仍然需要人类判断。底部这句**底线**请大家记住：**智能体在执行和实现审查上很强大，但它不能替代真正外部的批评。**

### 幻灯片 25：Looking Ahead: T6 Wraps Up, Lec10 Applies（前瞻：T6 收尾，Lec10 落地）
这一张收 T5。T5 给你看了哪些地方会出错——顺利路径代码、聚类聚错、上下文坍缩、RLHF 驱动的谄媚；接下来 T6 给整讲收口、并预告 Lec10。具体说：**T5 给那些"运行框架单凭自己防不住"的失败模式一一点了名；T6 把这张失败清单变成六条明确的评估标准，并讲清楚什么时候"不该"用智能体；再往后 Lec10 用四个做出来的案例范式把今天的逻辑跑一遍**——可复用技能、实证流水线、公开网络数据集、全生命周期协作者。底部主线弧告诉我们走完了 **T5**，下一站 **T6 收尾**。请大家带着这一节的警惕进入 T6：我们要把"怎么判断一个 AI 产物到底够不够格"这件事，正式立成标准。

### 幻灯片 2：Lecture 10 Preview: Four Concrete Workflow Patterns（Lec10 预览：四个具体工作流范式）
进入第一部分前，屏幕上有张分节页："Lec10 预览——从工作流逻辑，到具体案例研究。"这一张是张三列表："范式—Lec10 案例—学生会看到什么"，我读成对比性的话。**可复用技能**对应"论文评审工作流"，学生会看到分阶段的质量控制、引文核验、和编辑式过滤。**实证流水线**对应"MEPS 未参保"，会看到模式协调、调查权重、基准验证、出图。**公开网络数据集**对应"学者(Fellows)元数据"，会看到来源限制、数据溯源、缺失值纪律。**全生命周期协作者**对应"打杂式(glue-work)研究项目"，会看到理论、流水线设计、批判、论断纪律一整套。底部这句话点出两讲的接口：**Lec9 给的是工作流的逻辑，Lec10 展示同一套逻辑在不同研究产物上怎么变形。**

### 幻灯片 3：One Visual Hook from Lecture 10: MEPS Uninsurance（Lec10 的一个视觉钩子：MEPS 未参保）
这一张提前给大家看一眼 Lec10 案例二的成品图。案例二问的是：2000 到 2023 年，美国谁没有医保，以及 ACA（平价医疗法案）怎么改变了这个分布？屏幕中间这张图 `fig_overall_uninsurance.pdf` 就是答案的可视化——我讲课时会指着它说，这是一条总体未参保率随时间走的曲线，你能看到 ACA 生效前后那个明显的下台阶。为什么把这张图放在这里？两个理由：它是给**非宏观**经济学家也能秒懂的政策例子；而且它让大家看清——**一个工作流跑成功之后，那个"被验证过的实证产物"长什么样**。底部预告：Lec10 会补齐完整的流水线——提示词、模式协调、调查权重、外部基准、和子组图。这张图是钩子，下一讲给你看它背后的全过程。

### 幻灯片 4：Three Econometric Roles in Agent-Assisted Research（智能体辅助研究中的三种计量角色）
这一张借 Lec07 T4 的一个分类法，把四个案例看得更透。那个分类法是：**每一个从文本里导出的变量，都扮演三种角色之一——信号(signal)、结果(outcome)、或工具变量(instrument)。** 屏幕上这张表把四个范式套进这三个角色，我横着读一行做示范：实证流水线 MEPS 里，"信号"是未参保率、"结果"是医保覆盖估计、"工具变量"是调查加权的协调。其余三行同理——可复用技能（论文评审）对应方法论严谨度/评审质量/分阶段评分量规；公开数据集（学者）对应领域归属/溯源日志/来源限制规则；全生命周期协作者（打杂）对应研究想法/已验证的论断/智能体加领域专家的批判。底部这句话点出分类法的用处：**同一套智能体工具箱，四种研究设计。** 这个分类法逼你问一个好问题——**智能体的产出，在你的推断里到底扮演什么角色？**

### 幻灯片 5：What to Watch for in Lecture 10（Lec10 里要留意什么）
这一张给大家四个"看点"，进 Lec10 时带着它们看。**论文评审**：看一个可复用技能怎么把一句模糊的提示词，变成一套分阶段的质量控制工作流。**MEPS 流水线**：看一个实证问题怎么变成一个被验证过的面板和一组图。**学者数据集**：看数据溯源和缺失值规则，怎么和代码一样要紧——甚至更要紧。**打杂式项目**：看智能体式 AI 怎么当一个全生命周期协作者，却**不**取代人类的论断纪律。底部这句话是 Lec9 到 Lec10 的桥：**今天这一讲讲清工作流的逻辑，下一讲展示它能产出的产物。**

### 幻灯片 6：Six Criteria for Any AI-Assisted Research Output（任何 AI 辅助研究产物的六条标准）
进入收尾部分前，屏幕上有张分节页："收尾——工作流改变了什么，什么仍归人类。"这一张是整讲的压舱石。还记得 T1 那张"五条评估准则"吗？这里把它正式升级成**六条研究级判据**——在你接受智能体产出的任何脚本、图、表之前，先拿这六个问题过一遍。屏幕上是一张带勾选框的清单，我逐条读：**一、可复现(Reproducibility)**——模型、提示词、随机种子都钉死，合作者能从一个干净的克隆重跑出来。**二、可验证(Verifiability)**——数学、数据流、量级，都能被独立地重新核对。**三、可审计(Auditability)**——完整的提示词/输出日志，让审稿人能追到"逻辑在哪里偏离了规格"。**四、成本(Cost)**——披露真金白银（还有复制者的成本），不只是你自己花了多少。**五、速度(Speed)**——省下的墙钟时间和人工小时，要**扣掉**验证和调试的代价。**六、技能投资(Skill investment)**——团队是在积累耐用的能力，还是在悄悄让能力萎缩？底部那句话是这张清单的判决：**只要有任何一条答案是"否"或"我不知道"，这个产物就还没到研究级。**

### 幻灯片 7：Three Things AI Cannot Do — Regardless of Capability（AI 做不到的三件事 — 无论能力多强）
这一张点名三件**无论模型多强也做不到**的事，请大家记住它们是范畴上在系统之外的，不是等规模再大一点就能补上的缺口。第一，**识别(identification)**——选出能回答因果问题的那份变异。大语言模型不知道哪个冲击是外生的、哪个工具变量是有效的、哪个事件窗口被污染了；它能**描述**各种识别策略，但**不能为你这个具体场景"背书"**任何一个。第二，**福利(welfare)**——选定那个定义"什么叫好"的目标函数。帕累托权重、规划者的贴现率、公平与效率的取舍——这些是规范性选择，必须由研究者自己来担。第三，**判断(judgment)**——选出哪个问题值得问。AI 是针对一个**给定的**目标去优化的；而唯有经济学家能决定，哪个目标是有趣的、新颖的、与政策相关的。底部这句话请大家记死：**这三样不是随模型变大就会消失的缺口——它们在范畴上就处在系统之外。**

### 幻灯片 8：When NOT to Use an Agent（什么时候不要用智能体）
这一张把那六条判据反过来用——当成一条**边界**：有些研究任务，智能体的额外开销大过收益，或者它的失败代价太高。逐条看：**一行脚本和孤立的小改动**——一个两行的 `sed`、一张一次性的图，根本没有"验证面"留给运行框架去增值，直接打开编辑器。**深度私有或无文档的流水线**——如果那些约定只活在某一个人脑子里，智能体没东西可读；你把流水线写到"能交代清楚给智能体"的程度所花的时间，跟你自己动手修好它的时间是一样的。**严格的确定性保证**——做数值可复现审计、监管流水线、复制包时，模型的非确定性是运行框架压不住的隐患；钉死了跑，别让智能体重试。**提示词可能泄露的受限数据分析**——如果粘一列就会违反 IRB 或 HIPAA，智能体根本不该进这个回路，套用 T5 那几条安全变通办法。**你还没有基准的任务**——没有验证手段，更快的产出只意味着**更快地错**；先定义 V0 基准，**再**把智能体请进来。底部这条**实践法则**一句话收：**智能体最有用的场景，是工作有边界、可验证、可重复；这三样一个都没有？那就别用智能体。**

### 幻灯片 9：Trust but Verify（信任，但要核验）
这一张给一套很具体的核验动作，五条，每一条都能当场做。第一，**亲手复算一个统计量**。第二，**用另一个包或另一个脚本，交叉核对一个结果**。第三，**测一个极限情形、或一个零方差基准**——这正是同伦纪律里的"设零复原"。第四，**在经济学进入的地方，逐行读代码**。第五，**问一句：这个量级和符号说得通吗？** 底部这句话请大家加重听，它是整讲验证纪律的态度：**这不是可有可无的形式主义——正是它，把"快出来的代码"变成"站得住的研究"。**

### 幻灯片 10：What Changes for Economic Research（经济研究会改变什么）
这一张冷静地盘点：这套工作流到底改变了什么。四条：从**问题到第一个结果的距离**缩短了；更多的设定变得**便宜到值得一试**了；可复现性**反而可能改善**——因为工作流被写下来了；而那份溢价，从**打字速度**，转向了**设计、判断、与验证**。底部这句话是整讲反复敲打的主题，请大家记牢哪些事仍然姓"人"：**仍然归人类的，是提出那个问题、选定那个设计、了解那份数据、以及解释那个产出。**

### 幻灯片 11：You Are the Research Architect（你是研究的建筑师）
这一张是整讲的点题。屏幕中央那两行大字，我念出来：**"智能体能很快地把砖砌上，但结构仍然由你来设计。"** 下面四条，正好对应 Lec06、也对应本讲反复出现的那五根支柱——薄弱的规格，产出错的模型；薄弱的算法选择，产出又慢又误导的计算；薄弱的数值判断，产出脆弱的结果；薄弱的代码素养，产出没人核验过的输出。底部这句话纠正一个常见的误解，请大家带走：**这一讲不是要你交出专业能力，而是要你把精力重新分配到研究中那些依然稀缺的部分上去。**

### 幻灯片 12：First Exercise and Looking Ahead（第一个练习与前瞻）
这一张给大家布置一个最好上手的第一个练习：**挑一个你的旧项目，让智能体帮你安全地把它整理一遍。** 四步：把项目纳入 Git；写一个简单的 `CLAUDE.md`；找出一个值得编码成技能的重复工作流；把整理后的项目重跑一遍、对比输出有没有变。这个练习把今天讲的 Git 安全网、项目大脑、技能、和"重跑对照"的验证纪律，一次性都用上了。底部预告：**Lec10 我们回到案例研究，让大家亲手跑一条完整的工作流。** 最后一句——如果你想要实验课的搭建细节，看附录。

### 幻灯片 13：Appendix A: Installing One Terminal Agent (Dated)（附录 A：安装一个终端智能体（有时效））
进入附录前，屏幕上有张分节页："附录——搭建笔记与有时效的产品细节。"（以下都是附录/选讲，时间紧可以跳过。）这一张用 Claude Code 在 macOS 上举例，给三步操作，我讲它们各自干什么、不抠语法。第一步，**装运行时**——Claude Code 要 Node.js（`brew install node`，或去 nodejs.org 下 v18 以上），Aider 要 Python，别的工具类推。第二步，**装智能体 CLI**——`npm install -g @anthropic-ai/claude-code` 装 Claude Code，注释里那两行分别是 OpenAI Codex CLI 和 Aider 的装法。第三步，**验证**——`claude --version` 看版本，然后 `cd` 进你的项目文件夹再敲 `claude`。这里有一条 **Mac + OneDrive 注意**：启动智能体前，永远先 `cd` 进项目文件夹；从 `/Volumes/...` 这种路径直接跑，可能触发权限错误。最后这条**时效提示**很重要：订阅档位、模型 ID、安装命令每几个月就变，**讲课或开实验课前，先去官方文档重新核对一遍。**

### 幻灯片 14：Appendix A2: Setup for the Lab（附录 A2：实验课的设置）
这一张是给实验课的一张轻量搭建清单（附录/选讲）。四条：装一个终端智能体，确认它能启动；建一个项目文件夹，里面放一个项目专属的系统提示文件（`CLAUDE.md`、`AGENTS.md`、或 `GEMINI.md`，看你用哪个工具）、一个 `scripts/`、一个 `output/`；确认 Python 或 R 能从终端跑起来；第一次会话**保持小**——一个文件、一个检查、一个输出。底部还是那条**时效提示**：确切的搭建步骤、套餐、速率限制变得很快，开课前请重新核对官方文档。

### 幻灯片 15：Appendix B: Keybindings and Minimal Templates（附录 B：快捷键与最小模板）
这一张左右两栏，是一张速查卡（附录/选讲）。左栏**几个有用的命令**：`/compact` 压缩会话、`/clear` 清空会话、`Esc` 打断、`/` 调出斜杠菜单。右栏是一个**最小的项目系统提示模板**——不管文件叫 `CLAUDE.md`、`AGENTS.md` 还是 `GEMINI.md`，骨架就四行：Project（项目是什么）、Goal（目标）、Language（语言）、Checks（检查）。我点一句：别小看这四行，一个能用的项目大脑，往往就是从这么一个最小模板长起来的。
